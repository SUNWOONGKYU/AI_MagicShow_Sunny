# Sunny의 AI Magic — 48개 종합 정리

*4,000시간 이상의 실전 경험을 통해서 터득한 엑기스*

**Claude Code를 중심으로 한 AI 사용법 관련 꼭 알려주고 싶은 것 목록**

분류 방식: 운용 단계별 5개 그룹

## 그룹 1. 사고·기획 (작업 시작 전)

작업에 들어가기 전 깊이 생각하고, 방향을 잡고, 계획을 세우는 단계의 팁들. AI에게 바로 시키지 않고 충분히 사유하는 데 쓰는 방법론.

### 2) 스무고개 문답을 통한 브레인스토밍하기
AI와 일문일답을 주고받으며 아이디어를 좁히고 발전시키는 방식. 막연한 주제도 스무고개 식으로 풀어가면 구체화됨.

### 3) 아젠다별로 AI에게 하나씩 설명듣고 승인하기
큰 작업을 한 번에 시키지 말고, 작업 항목별로 AI 설명을 듣고 사용자가 승인 후 다음 단계로 진행하는 방식. 통제력과 정확도 모두 확보.

### 12) 3개 이상 대안 제시하고 권고안 표시하게 하기
"하나만 알려줘"가 아니라 "3개 이상 대안 + 각 장단점 + 최종 권고"를 시키는 패턴. AI가 단답으로 빠지는 것을 방지하고 다관점 검토 강제.

### 13) 3개 이상의 분야별 전문가 페르소나 AI가 참여해서 토론하여 방안 제시하게 하기
**반드시 Devil's Advocate 참여 필요.** 전문가 역할을 AI에게 부여하고 그들끼리 토론시켜 다관점 검토. Devil's Advocate가 있어야 진짜 약점이 드러남.

### 14) SAL(Stage, Area, Level) 3차원 좌표를 활용해서 대규모 작업 계획 세우기 or 분해하기
큰 작업을 단계(Stage) × 영역(Area) × 수준(Level) 3차원 좌표로 매핑해서 분해하는 본인 고유 방법론. 누락 없는 분해와 진척 관리 가능.

### 25) 5단계로 나누어 순차적으로 작업시키기
한 번에 다 시키지 말고 5단계로 쪼개서 순차 진행. 각 단계별로 결과물 확인하며 다음 단계로 넘어가는 표준 워크플로우.

### 31) Data → Information → Decision의 Loop 이해하고 활용하기
데이터를 정보로 가공하고, 정보를 의사결정으로 연결하는 순환 구조 의식적 활용. AI 작업의 본질적 흐름.

### 34) Plan Mode 활용해서 실행하기 전에 계획부터 세우기
Shift+Tab 두 번으로 Plan Mode 진입. AI가 읽기·분석·계획만 시키고 실행 차단. 사용자 승인 후 실행 모드 전환. 위험 작업·큰 리팩토링 전 필수. 34번 마인드셋의 실행 도구.

### 35) SAL Grid 개발방법론(특허출원된)을 사용해서 한번에 끊김없이 개발업무 진행하기
14번 SAL을 개발 업무에 특화시킨 본인 특허 방법론. 끊김 없는 개발 흐름 확보.

## 그룹 2. 환경 설정·자산 구축 (작업 인프라)

작업을 잘 굴러가게 하는 인프라 — 도구, 스킬, 명령어, 자산을 갖추는 단계의 팁들. 한 번 잘 세팅해두면 매 작업 시간 절약.

### 4) WiKi_LLM과 Obsidian을 활용한 지식베이스 관리하기
지식을 외부 시스템에 누적시켜 AI 작업 시마다 끌어 쓸 수 있도록 자산화. AI 운용의 장기 메모리 역할.

### 8) 엔비디아에서 공개한 NeMoTron 100만 한국인 합성 데이터셋 활용하기
한국어 작업 시 활용 가능한 대규모 합성 데이터셋. 본인 챗봇 학습·검증 등에 활용.

### 15) 반복되는 프로세스가 파악되면 SVG 등의 그림 형식으로 관계도 및 흐름도를 만들어서 아키텍처로 정리하고 스킬로 만들어서 사용하기
반복 패턴 발견 → 시각화 → 스킬 자산화의 3단계. AI 운용을 점진적으로 자동화하는 핵심 노하우.

### 22) 나를 위한 지능형 챗봇 만들어서 키우기
**아바타형(전문지식 제공용 or 특기 전수용)·도우미형(업무용 or 일상생활용) 구분.** 단순 사용 넘어 본인만의 챗봇을 점진적으로 학습·개선시키며 자산화.

### 23) CLAUDE.md 파일 잘 활용하기 — 보안·언어 운용·문서 작성 규칙 박아두기
프로젝트별·전역 CLAUDE.md에 다음을 박아두기: ① 작업 규칙 ② 보안 가드(읽지 말아야 할 폴더·비밀키 패턴 차단) ③ 언어 운용 규칙(한국어 출력, 사고 영어 등) ④ 한국 공공 문서 작성 양식. 매번 시키지 않아도 자동 적용.

### 28) 나에게 필요한 Skill, Agent 등의 도구를 쉽게 찾아서 활용하기
필요한 외부 스킬·에이전트 발굴·검증·도입 능력. revfactory/skills 같은 검증된 저장소 활용.

### 36) 개발업무는 내 컴퓨터 C드라이브에서 하되 백업 폴더를 G드라이브에 만들어두고 동기화 하기
작업 폴더 이중화. C드라이브 작업 + G드라이브 백업으로 데이터 손실 방지.

### 38) Hooks 활용하기
Claude Code의 훅(PreToolUse, PostToolUse, Stop, SessionStart 등) 활용. 품질관리·포맷팅·검증을 사용자 명령 없이 자동 발동. 6번 품질관리 스킬을 자동화로 격상시키는 도구.

### 39) Slash Commands 활용하기
`.claude/commands/`에 마크다운 파일로 본인만의 단축 명령어 만들기. `/특허초안`, `/3대안`, `/품질4종` 등. 반복 작업을 타이핑 한 번으로 압축. Skill로 만들기 전 단계의 가벼운 자산화.

### 40) MCP 서버 활용하기
기성 MCP 서버 연결로 외부 시스템(Notion, Slack, DB, 파일시스템 등)과 직접 통신. 17번이 CLI 레벨 협업이라면 MCP는 데이터·시스템 레벨 협업. 필요 시 본인 전용 MCP 서버도 구축.

### 41) Git Worktree로 병렬 브랜치 작업하기
같은 저장소를 여러 폴더에 동시 체크아웃해 각 폴더마다 별도 Claude Code 인스턴스로 병렬 작업. 5번이 가로 확장(다대 컴퓨터)이라면 worktree는 세로 확장(단일 머신). 공동 작업 시 충돌 방지에 필수.

### 43) `--dangerously-skip-permissions` 활용하기 — Hooks 가드레일과 결합해서 안전하게
모든 승인 단계 건너뛰는 옵션 사용으로 속도 확보, 동시에 38번 Hooks의 PreToolUse로 위험 명령(파일 삭제 등) 사전 차단. 5번·9번·42번 같은 대규모·자동화 운용의 사실상 필수. 38번과 짝.

### 44) `/model` 명령으로 작업에 맞는 모델 선택하기
Opus(복잡한 추론·기획), Sonnet(균형·일반 코딩), Haiku(단순 반복·요약) 의식적 선택. 5번 30개 운용 시 역할별 모델 배정으로 비용·속도 최적화. 32번과 짝.

### 48) Claude Code HUD 사용하기
Status Line으로 컨텍스트·Rate Limit·도구·서브에이전트·팀메이트·Git 상태 실시간 가시화. 외부 플러그인(Claude HUD, cs, ccusage 등)이 컨텍스트·사용량 정확도 한계가 있어 본인 맞춤 셸 스크립트로 직접 작성. 별도 작업지시서로 구현.

## 그룹 3. 작업 실행·운용 (실제 작업)

실제 작업을 굴리는 단계의 팁들. 단일 AI를 어떻게 다루는가, 여러 AI를 어떻게 운용하는가, 컨텍스트를 어떻게 관리하는가.

### 1) Dual Mode 실행하기
두 가지 모드를 병행 운용하는 본인 고유 방식. (구체 정의는 본인 운용 노하우)

### 5) 크롬 원격 데스크탑을 통한 모바일에서 원격 접속하여 작업시키기
**5개 컴퓨터에 6개씩 총 30개 Claude Code를 아무곳에서나 돌리기.** 가로축 양적 확장의 극단적 사례. 모바일에서도 운용 가능.

### 9) 군대의 소대 편제방식을 활용한 대규모의 AI 투입하기
군 조직 편제 비유로 AI 군단 운용. 소대장(주력 AI) + 소대원(서브에이전트·팀메이트) 구조. 27번 Agent Teams 공식 기능과 결합 시 강력.

### 10) MBO(Management By Objective; 목표에 의한 관리) 방식으로 작업시키기
경영학 MBO 방식 차용. 목표 설정 → AI에게 부여 → 결과 평가의 사이클. AI를 직원처럼 다루는 관리 방식.

### 17) Claude Code를 오케스트레이터로 두고, Gemini CLI, Codex CLI, Grok CLI를 특화된 실행 도구로 사용하기
**AI간 대화형 협업을 넘어서 실행형 협업으로 가는 방법.** 메인 Claude Code가 지휘자 역할, 다른 CLI들은 특화 실행 도구. 멀티 모델 운용의 핵심 패턴.

### 18) 대량 검색 시 토큰비를 줄이려면 네이버·구글 검색 활용하기
AI 자체의 웹 검색은 토큰 비용 큼. 대량 검색은 네이버·구글로 직접 처리해 비용 절감.

### 26) 1개의 AI에게 Multi Role로 작업시키기
한 AI 인스턴스에 여러 역할을 동시에 부여해 운용. 9번이 다대 인스턴스라면 26번은 단일 인스턴스 안에서의 다역할.

### 27) 일반 Subagent와 Agent Teams 차이를 이해하고 작업시키기
- **Subagent**: 단일 세션 내 하위 작업자, 메인에게만 보고
- **Agent Teams** (공식 기능, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 활성화): 팀리더 + 팀메이트들, 팀메이트 간 직접 통신, 각자 독립 컨텍스트 윈도우

### 30) 컨텍스트 관리 — 모니터링·수동 Compact·자동 저장의 3종 세트
Auto Compact 기능 끄고 수동 Compact로 운용. 컨텍스트 사용량 의식적 모니터링(48번 HUD 활용), Compact 전 작업내용 지정 폴더에 자동 저장, 세션 분할·인계 노트로 장기 작업 정보 손실 방지.

### 42) `claude -p` 헤드리스 모드로 자동화하기
대화형 UI 없이 명령줄에서 한 번에 호출. 셸 스크립트·크론·CI 파이프라인에 통합 가능. 매일 새벽 자동 실행, 폴더 100개 파일 일괄 처리 등. 11번 1일 1영상의 진짜 자동화 인프라.

### 45) `/resume`으로 과거 세션 재개하기
갑작스런 종료·미저장 상황 복구용. **단, 컨텍스트가 금방 차므로 비상·짧은 이어가기에만.** 평상시 컨텍스트 운용은 30번에 의존.

## 그룹 4. 결과물·검증 (완성도)

실제 결과물을 만들고 품질을 끌어올리는 단계의 팁들. 무엇을 만드는가, 어떻게 검증하는가.

### 6) 작업결과물에 대해서 수시로 4종의 품질관리 스킬을 실행하여 완성도 높이기
4종 품질관리 스킬을 본인이 정의해 보유. **스스로 비판시키기(약점·빠진 것·반박점 찾아내기)가 4종 검증에 반영되도록.** 단순 칭찬 받기가 아닌 본인 결과물 자기 비판하게 시키는 운용.

### 7) 사업 아이디어가 떠오르면 그것으로 특허출원서 작성하기
**지구상에 나와 있는 관련 논문·특허 등을 모두 조사시켜서 차별점 정립하기.** AI를 특허 차별점 도출 엔진으로 활용. 22번 챗봇·28번 도구 결합 시 강력.

### 11) 유튜브 영상 한방에 제작하기 → 유튜브에 1일 1영상 올리기
영상 제작 전 과정(스크립트·이미지·편집)을 AI로 처리. 47번 멀티 모델 이미지 + 42번 헤드리스 결합 시 진짜 1일 1영상 자동화 가능.

### 16) 공유하고 싶은 내용이 있으면 html 파일로 만들어서 Vercel 활용하여 신속 배포하기
HTML 결과물 + Vercel 무료 호스팅으로 즉시 배포. 24번·22번 결과물의 외부 공유 채널.

### 21) AI는 틀릴 수 있음을 인정받는 지구상에서 거의 유일한 존재임을 인정하기
**다단계 검증을 필수적으로 하되 그러한 특성으로 촉발되는 창발 포착하기.** AI의 오류 가능성을 검증으로 막되, 그 과정에서 오히려 새로운 통찰이 나오는 창발 현상을 잡아내는 운용 철학.

### 24) 미니 풀스택 웹사이트 5시간 이내에 만드는 것 연습하기
풀스택 웹사이트 단시간 제작 훈련. AI 활용 능력의 종합 척도. 24번을 5시간에 한다는 건 19번 트랙터 운전 능력의 증명.

### 29) HWP/HWPX 자유자재로 다루기 — 읽기·쓰기·변환 + 한국 공공 양식 자산화
HWP 바이너리 + HWPX 양 포맷 처리. 읽기·쓰기·변환 모두 능숙. 한국 공공 표준 양식(기안문·보고서·공문)을 스킬로 자산화. 본인 본업(공공 AX) 직결.

### 46) 스스로 스크린샷 찍어서 문제점 찾아 스스로 수정하기
Claude Code가 결과물 화면을 자기가 캡처해서 자기가 검증하고 자기가 고치는 자율 루프. 21번·6번·31번을 한 작업 안에서 자동 실행. 24번·11번·16번 시각 결과물의 마무리 품질 결정타.

### 47) 멀티 모델을 활용한 이미지 제작 프로세스 실행하기
5개 모델(Gemini류 + ChatGPT류) × 3장씩 = 15장 생성 → 모델별 베스트 1장씩 5장 선별 → Pillow 후처리로 완성. 17번·9번·12번·15번을 이미지 제작에 결합한 본인 운용 노하우.

## 그룹 5. 마인드셋·최적화 (관통 원칙)

특정 단계가 아니라 모든 작업에 관통하는 운용 철학과 비용·효율 최적화 원칙.

### 19) 공사용 삽질/추수용 낫질 개선방안을 연구하지 말고 포크레인/트랙터 운전 연습하기
도구의 패러다임 전환 비유. 작은 개선 헤매지 말고 차원이 다른 도구 익히기에 시간 투자. 본 시리즈 전체를 관통하는 핵심 메시지.

### 20) 문서화는 나중에 하고 일단 만들어보고 테스트해보기
완벽한 기획·문서 후 실행이 아니라 빠른 프로토타입 + 테스트 우선. 다만 34번 Plan Mode와 충돌해 보일 수 있어 — 단순 작업은 20번, 큰 작업은 34번 식으로 구분 운용.

### 32) 다른 AI를 API를 통해서 대규모로 사용해야 할 경우에는 API 비용 최적화 방안을 미리 설계해서 사용하기
대규모 AI 호출 시 비용 통제 사전 설계. 18번(검색 비용), 44번(모델 선택)과 짝. 5번·9번·42번 대규모 운용 시 필수.

### 33) Claude 앱과 Code의 차이점을 이해해서, 브레인스토밍 등(멋진 문구 만들기 포함)은 앱에서 하고 실행은 Code에서 하기
도구별 특성 활용. 앱 = 사고·문구·창의, Code = 실행·자동화. 같은 사고 작업도 어느 도구에서 하느냐에 따라 결과 달라짐.

### 37) 피크타임 사용시간(저녁 11시부터 새벽 3시까지) 피하기
사용량 한도·응답 속도 관점에서 피크타임 회피. 본인 운용 패턴에서 도출한 시간대 노하우.
