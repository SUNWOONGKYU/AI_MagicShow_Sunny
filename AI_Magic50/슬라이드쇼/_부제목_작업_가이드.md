## 2. 한 챕터 처리 워크플로우 (반드시 이 순서)

### Step 1. 챕터 파일 읽기
```
Read "G:/내 드라이브/333_자료공유폴더/Sunny_Magic_Show/AI_Magic50/상세/md_new번호/{NN}_*.md"
```

frontmatter에 이미 `subtitle:` 가 있으면 건너뛰고 다음 챕터로.

### Step 2. 원본 리스트에서 해당 항목 찾기
```bash
grep -n "{NN})" "G:/내 드라이브/.../Claude Code를 중심으로 한 AI 사용법 관련 꼭 알려주.txt"
```
원본 리스트의 "—" 뒤 문구가 부제목 후보 1순위 재료.

> 단, 본 책의 챕터 번호와 원본 리스트 번호는 **다를 수 있음**. 챕터 frontmatter의 `sources:` 항목에 보통 `(#NN)` 형태로 원본 번호가 적혀있음. 또는 제목 키워드로 grep.

### Step 3. 본문 핵심 3줄 추출
한 줄 정의 / 왜 중요한가 첫 단락 / 본문에서 가장 압축된 한 줄. 이 3줄이 부제목 재료.

### Step 4. 부제목 3~4개안 제시 + 추천

표 형식으로 사용자에게 제시:

```
## 📖 #NN — {제목}

| 항목 | 값 |
|------|-----|
| 챕터 번호 | NN |
| 그룹 | {group_id} ({group_name}) · order {order_in_group} |
| 타입 | {type} |
| 특허 | {patent or '없음'} |
| 현재 제목 | {title} |
| 현재 부제목 | (없음) |
| 원본 리스트 매핑 | #{원본번호} {원본 문구} |

본문 핵심 3줄:
1. L{N}: "..."
2. L{N}: "..."
3. L{N}: "..."

### 부제목 안

A안 — ...
B안 — ...
C안 — ...

### 추천: A안 (또는 다른 안)
이유: ...
약점 + 보완: ...

승인하시거나 다른 안 골라주세요.
```

### Step 5. 사용자 승인 대기

사용자가 "A" / "a" / "A안으로 진행" / 직접 문구 입력 / "다른 안 제시" 중 하나로 응답.

- 본문과 매칭이 안 된다고 하면 부제 다시 제시
- 본문 수정 요청 시 본문도 보완 (frontmatter 그대로 두고 본문만 Edit)

### Step 6. frontmatter에 subtitle 추가

Edit tool 사용:
```python
old_string: 'title: "{title}"\ntype: {type}'
new_string: 'title: "{title}"\nsubtitle: "{확정된 부제목}"\ntype: {type}'
```

> 주의: subtitle은 title 다음 줄, type 이전에 삽입.

### Step 7. HTML 재생성

```bash
cd "G:/내 드라이브/333_자료공유폴더/Sunny_Magic_Show/AI_Magic50/상세/md_new번호" && python _md_to_html.py
```

→ `상세/md_new번호/book/*.html` 50개 재생성. 슬라이드쇼 폴더에 자동 반영되는지 확인 필요한 경우 추가 복사 단계가 있을 수 있음(현재 워크플로우에선 자동).

### Step 8. Vercel 배포

```bash
cd "G:/내 드라이브/333_자료공유폴더/Sunny_Magic_Show/AI_Magic50/슬라이드쇼" && vercel --prod --yes
```

배포 URL 마지막 3줄 출력 확인. 성공 시 사용자에게 보고:

```
✅ #NN 완료

- 부제목: "..."
- 배포 완료: https://sunny-ai-magic-50.vercel.app/

다음 #{NN+1} 진행할까요?
```

### Step 9. 사용자 확인 후 다음 챕터로

"응 #NN+1 진행해" 또는 유사 응답 받으면 Step 1부터 반복.

## 3. 부제목 작성 원칙

### 길이
- **35~70자 (한글 기준)**. 너무 짧으면 정보 부족, 너무 길면 슬라이드 표지에 안 들어감.

### 어조
- **본인 어투 유지** — 사용자(서니진)의 실제 어투("크레딧 폭탄", "본진", "비상 카드", "트랙터 운전" 등) 가능한 본문에서 그대로 가져옴.
- 존댓말·"~합니다" 금지. 명사형 또는 "~기/~함" 형 종결.

### 구조 — 권장 패턴 3가지
1. **A vs B 대비형**: "단발 위임 vs 독립 컨텍스트 협업" (#16)
2. **What + Why 결합형**: "외부 시스템과 데이터 레벨로 직접 통신하는 프로토콜" (#20)
3. **원본 리스트 인용형**: "갑작스런 종료·미저장 복구 전용, 평상시 금지" (#19)

### 금지 사항
- 본문에 없는 표현 임의 창작 금지
- "최고", "최강", "혁신적" 등 과장 형용사 금지
- 단순 동어반복(제목 그대로 다시 쓰기) 금지

### 본문과 매칭
부제를 정한 후 본문 핵심 메시지와 1~2개 키워드라도 직접 연결되는지 재확인. 매칭 약하면 다시 제시.

## 4. 본문 보완 시 원칙

사용자가 *"본문이 원리를 제대로 못 잡고 있다"* 라고 지적하면:

1. 사용자가 알려준 원리/사실을 그대로 본문에 반영 (창작 금지)
2. 기존 본문 어투·구조 유지
3. 표(table) 형태가 효과적이면 사용
4. 정량 데이터(수치·금액·횟수)는 본문에 명시
5. 출처 명확: 본인 실측 데이터 / Anthropic 공식 / 외부 자료 구분
6. frontmatter는 가능한 건드리지 않음 (subtitle만 추가)

## 6. 자주 만나는 함정

| 증상 | 원인 | 해결 |
|------|------|------|
| `subtitle:` 추가했는데 슬라이드에 안 보임 | HTML 재생성 안 함 | `python _md_to_html.py` 실행 |
| Vercel 배포는 됐는데 URL에서 변경 안 보임 | 캐시 / 빌드 미완료 | 1~2분 대기 후 새로고침 |
| 한글 경로 빌드 오류 | Next.js Turbopack 한글 미지원 | 본 프로젝트는 정적 HTML이라 무관 |
| Edit tool 오류 "old_string not unique" | 같은 문자열 여러 곳 | 더 긴 컨텍스트 포함시켜 unique 만들기 |
| 원본 리스트 grep 매칭 실패 | 챕터 ≠ 원본 번호 | 키워드로 grep, 또는 frontmatter `sources:` 확인 |

## 7. 절대 규칙

1. **사용자 승인 없이 frontmatter 수정 금지** — 부제는 반드시 3개안 제시 → 사용자 응답 → 적용.
2. **본문 임의 창작 금지** — 사용자가 알려준 사실/원리만 본문에 반영.
3. **배포 전 HTML 재생성 필수** — 순서: MD 수정 → HTML 재생성 → Vercel 배포.
4. **한 번에 한 챕터만** — 여러 챕터 일괄 처리하지 말 것. 사용자가 매 챕터 승인.
5. **자기 검증 금지** — 다른 인스턴스가 만든 부제를 자기가 적용해도, 한 번 더 사용자에게 보여줘 승인 받음.
