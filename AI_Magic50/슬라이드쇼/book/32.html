SUNNY AI MAGIC 50 · #32

Claude 앱과 Code의 차이 — 사고는 앱, 실행은 Code

브레인스토밍·멋진 문구는 앱, 실행·자동화·파일 접근은 Code
G5 · 환경 C타입

한 줄 정의

같은 Claude라도 앱(claude.ai)은 사고·문구·창의, Code(터미널)는 실행·자동화·파일 시스템 접근이라는 도구별 특성을 의식적으로 분리해 운용하는 원칙.

왜 이 노하우가 중요한가

본인 누적 운용에서 가장 흔한 실수는 Code에서 슬로건을 다듬고 앱에서 코드를 짜는 역방향 사용이었다. Code는 도구 호출 권한과 파일 접근이 강점이고, 앱은 깨끗한 컨텍스트와 대화형 사고가 강점이다. 둘을 섞으면 두 도구의 약점만 모인다 — Code의 컨텍스트는 도구 로그로 더러워지고, 앱은 실행이 막힌다.

브레인스토밍·멋진 문구·기획 토론은 앱에서 끝낸 뒤 결과만 Code에 주입하는 흐름이 본인 운용의 표준이 됐다.

핵심 개념

도구 특성 비교:

항목 앱 (claude.ai) Code (터미널)
강점 사고·창의·문구 실행·자동화·파일
컨텍스트 깨끗 (대화만) 도구 로그 혼합
도구 제한 (검색·아티팩트) 풍부 (Bash·Edit·MCP)
운용 단위 대화 1건 인스턴스 30개
비용 구독 정액 API 종량

(가격·플랜 출처: Anthropic Pricing, as of 2026-05-06)

본인 작업 분류: - 앱이 맞는 일: 슬로건·카피, 기획 브레인스토밍(#1), 페르소나 토론(#1) 초안, 특허 차별점 1차 도출(#27), 사업 아이디어 발산 - Code가 맞는 일: 풀스택 구현(#6), 30개 동시 운용(#31), 영상 자동화(#9), SAL Grid Stage 실행(#2), 헤드리스 배치(#12)

실전 사용법

1단계 — 작업 시작 전 "이건 사고인가 실행인가" 질문. 답이 사고면 앱, 실행이면 Code.

2단계 — 앱에서 발산·토론 후 결과물만 마크다운으로 추출. 토론 과정 전체를 Code로 옮기지 않는다.

3단계 — Code 첫 프롬프트에 앱에서 뽑은 결과를 인용으로 주입. CLAUDE.md(#32)에 "사고 산물 인용 형식"을 규정해두면 일관성 확보.

4단계 — Code에서 도중에 "멋진 문구가 필요해진 순간"이 오면 그 자리에서 만들지 말고 앱으로 이동. Code 컨텍스트가 슬로건 다듬기로 오염되면 30번 컨텍스트 관리가 무너진다.

5단계 — 결과 검수도 분리. 사용자 여정 검증은 Code(Playwright·#49), 카피 검수는 앱.

본인 운용 패턴: 아침 기획은 앱, 낮 실행은 Code, 저녁 발산은 다시 앱. 도구 전환이 곧 모드 전환이다.
