SUNNY AI MAGIC 50 · #23

멀티 모델 이미지 제작 프로세스

같은 프롬프트로 5개 모델 동시 생성, 비교·채점은 AI가 하고 사람은 마지막 1장만
G4 · 결과물 및 품질관리 B타입

한 줄 정의

5개 이미지 모델(Gemini 3 Pro 나노바나나 + Gemini Flash + GPT Image + DALL·E + Claude Design / 향후 FLUX·Ideogram·Recraft)에 같은 프롬프트로 각 3장씩 총 15장을 동시 생성 → Vision 1차 채점으로 모델별 베스트 1장씩 5장 추림 → Pillow 후처리로 라벨·워터마크·EXIF 입혀 마감 → Vision 2차 정밀 채점으로 골드 1~2장 자동 추천하는 깔때기형 워크플로우. 15장 중 1장 이라는 인지 부하 1/15 축소가 핵심.

왜 이 노하우가 중요한가

이미지 생성 AI를 한 모델만 쓰는 건 4,000시간 운용에서 가장 많이 본 비효율 중 하나다. 이유는 단순하다 — 같은 프롬프트라도 모델별 결과 편차가 너무 크다. 어떤 모델은 한글 텍스트가 깨지고, 어떤 모델은 투명 배경을 못 만들고, 어떤 모델은 사실적 사진엔 강한데 일러스트엔 약하다. 그러니 사용자가 한 모델만 시도해서 "AI 이미지 별로네" 라고 결론 내리는 건 표본이 잘못된 것이지 AI가 못한 게 아니다.

본인이 슬라이드 34번("스킬 5: 이미지 만들기")에서 강조하는 게 이 점이다. 모델 비교 → 선택 → 후처리 가 한 묶음이어야 한다. 그런데 사람이 이 비교를 매번 직접 하면 5장 비교만 해도 인지 부하가 크고, 15장 비교는 사실상 불가능에 가깝다. 그래서 AI 자체가 비교·채점을 하고 사람은 마지막 한 장만 본다.

이 깔때기는 "데이터 레이어 KPI ≠ 사용자 여정 KPI" 원칙을 이미지 분야에 적용한 결과다. 데이터 레이어 KPI("모델별 응답 200 OK") 만 보면 5장이 다 "성공"이지만, 사용자 여정 KPI("이 슬라이드에 쓸 만한 한 장")로 보면 5장 중 0장일 수도 있다. Vision 정밀 채점이 그 사용자 여정 KPI를 객관 점수로 고정한다 — 골드(85점 이상) 등급이 안 나오면 "안 만든 것과 같다" 가 본인 운용 원칙이다.

또 하나 — 이 워크플로우는 #22 멀티 CLI와 #14 소대 편제와 #46 3대안 권고안과 #24 시각화 스킬 자산화의 이미지 분야 결합이다. 5개 모델은 #22의 멀티 모델 정신, 15장 → 5장 → 1장 깔때기는 #14 소대편제의 팀 → 분대 → 개인 위계, 모델별 베스트 추리기는 #46 3대안 중 권고안 표시 패턴, Pillow 후처리 라벨링은 #24 시각화 자산화. 본인이 연결된 운용 이라 부르는 핵심 사례.

핵심 개념

4단계 깔때기 (스킬 SKILL.md 인용)

[1] 15장 생성    5모델 × 3변형  →  ThreadPool 병렬 + Gemini 29키 로테이션
       ↓
[2] 1차 채점     best_of_n.py · 모델별 베스트 1장 → 5장
       ↓
[3] Pillow 마감  라벨·워터마크·EXIF·비율 통일 → labeled/*.png
       ↓
[4] 정밀 평가    final_eval.py · 가중 100점 → 골드/실버/브론즈
       ↓
   PO는 골드 1~2장 중 한 장만 고른다 (인지 부하 1/15)

각 단계가 분리되지 않고 한 명령(compare_models.py "프롬프트" --best-of 3)으로 끝난다.

5개 모델 — 강점이 다른 이유로 다 쓴다

모델 강점 약점
Gemini 3 Pro Image (나노바나나) 4K, 투명 배경, 멀티 레퍼런스 14장, 한글 비교적 안정 사진 사실감은 GPT보다 약간 아래
Gemini 3.1 Flash Image 속도·가격, 일반 용도 균형 디테일은 Pro 미만
Gemini 2.5 Flash Image (구버전) 안정적, 비용 가장 낮음 신모델 대비 품질
GPT Image 1 / 2 사실적 사진·제품 목업, 마스킹 편집 투명 배경 미지원
DALL·E 3 예술적 일러스트, 창의적 해석 텍스트 환각 강함

향후 통합 대기: FLUX(SOTA 사진), Ideogram(텍스트 1위), Recraft(벡터 SVG), Claude Design(웹 UI).

Vision 정밀 채점 — 100점 가중 (스킬 SKILL.md)

항목 가중치 평가 내용
프롬프트 의도 부합도 30 요청 구도·단계·요소 그대로 구현됐나
텍스트 정확도 20 라벨·제목 글자 오타·환각 없는가
시각적 완성도 20 색·균형·디자인 품질
정보 전달력 15 한눈에 의도가 전달되는가
레이아웃 정렬 15 화살표·카드 정렬 깔끔도
등급 점수 의미
GOLD ≥85 프로덕션 즉시 사용 가능
SILVER ≥70 소규모 보정 후 사용 가능
BRONZE ≥50 컨셉 검토용
CUT <50 사용 불가

top_picks 자동 선정: 골드만 → 없으면 실버 → 그것도 없으면 1위 1장. 즉 골드가 없으면 "이 프롬프트 다시 짜라" 신호.

Pillow 후처리 5종 — AI가 못 하는 마감

단계 효과
비율 통일 모델별 16:9 / 1536×1024 / 1792×1024 → 16:9 강제
워터마크 우하단 반투명 "BuzzLab AI · /ai-image-기본"
모델명 라벨 하단 다크 네이비 밴드 + 한글 모델명
콜라주 5장을 2×3 격자 1장으로 합성(SNS 1장 업로드)
EXIF 메타 PNG tEXt에 프롬프트·모델·생성일 주입

핵심은 "AI는 그림을 그리고, Pillow는 마감을 입힌다" — AI가 한글 텍스트 깨뜨려도 라벨은 정확. 5개 모델 결과가 비율·해상도·스타일 제각각이어도 동일 프레임으로 묶임.

결합되는 4개 스킬

본인 노하우 이미지 워크플로우에서의 역할
#22 멀티 CLI 5개 모델 동시 호출 = 이미지판 멀티 모델 운용
#14 소대 편제 15→5→1 깔때기 = 분대→소대→소대장 위계
#46 3대안+권고안 모델별 베스트 5장 = 5대안, 골드 1~2장 = 권고안
#24 SVG 스킬 자산화 반복 패턴(라벨·워터마크·콜라주)을 Pillow 스크립트로 자산화

실전 사용법

표준 호출 한 줄

python "$HOME/.claude/skills/ai-image-기본/scripts/compare_models.py" \
  "프롬프트 한 줄" \
  --best-of 3 \
  --outdir "C:/Users/home/Desktop/{작업명}_compare"

→ 활성 모델 전부 호출 → 15장 생성 → Vision 1차 채점 → Pillow 마감 → Vision 2차 정밀 평가 → index.html 자동 생성·브라우저 오픈 → Google 드라이브 동기화.

본인 환경에 Gemini 29키 로테이션 사전 등록(C:/Users/home/.gemini_keys, BuzzLab .env.local에서 추출 28개 + 환경변수 1개)되어 있어 quota 초과로 멈출 가능성 거의 없다.

비용 가드레일 — 2단계 운용

  1. 탐색: quality=low (GPT) / size=1K (Gemini)로 구도·스타일 확정 — 5장 ≈ $0.03
  2. 최종 렌더: 확정안만 quality=high / size=2K~4K — 1장 ≈ $0.21

탐색·최종을 한 번에 high로 돌리면 비용 7배. 첫 호출은 무조건 low 탐색이 본인 절약 패턴.

골드 1장이 정말 슬라이드에 들어맞는지는 #49 스크린샷 자율 검증 으로 실제 사용 맥락에서 한 번 더 확인. "갤러리에서 골드" 와 "슬라이드에 넣었을 때 어울림" 은 다른 KPI다.

본인 운용 패턴

5개 모델 × 3장 = 15장 자동 생성 → 5장 추림 → 1장 선택. 사람은 1/15만 본다. 본인 운용에서 이 깔때기 도입 전후로 이미지 작업 1건당 평균 시간이 25분 → 6분으로 줄었다 — 비교·결정 시간이 핵심 병목이었던 것.

골드 등급이 안 나오면 "이미지가 부족" 이 아니라 "프롬프트가 부족" 이라는 시그널. 모델 더 바꾸지 말고 프롬프트 재작성 — 서술형 묘사 + 스타일 명시 + 조명·구도 + 텍스트는 따옴표.

자기 검증 금지 — final_eval.py의 Vision 채점은 생성한 모델과 다른 모델이 채점하도록 설계. Claude가 만든 걸 Claude가 채점하면 점수 인플레가 일어난다는 누적 학습.

본인 운용에서는 슬라이드(MagicShow강의자료/index_테스트버전.html 50장) 이미지 자산도 이 깔때기 산출물 중심이다. 슬라이드 34번 "스킬 5: 이미지 만들기" 가 본 노하우의 강의용 정리.
