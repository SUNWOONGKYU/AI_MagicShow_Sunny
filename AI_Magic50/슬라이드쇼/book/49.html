SUNNY AI MAGIC 50 · #49

HWP/HWPX 파일 처리

두 포맷 한 도구로 — 읽기·변환·표준 양식 4종 자산화
G6 · 기타 B타입

한 줄 정의

HWP(바이너리)·HWPX(XML) 양 포맷을 읽기·변환·표준양식 생성까지 자유자재로 처리하고, 한국 공공기관 표준 양식(기안문·검토보고서·공문·회의록)을 재사용 가능한 스킬 자산으로 박아놓는 것. doc-generator-기본 스킬 Phase 5(HWP) 의 모든 경로를 본인 공공 AX 사업 흐름에 맞춰 단축·재구성한 운용 패턴.

왜 이 노하우가 중요한가

본인 본업이 공공 AX(공공 인공지능 전환) 다. 공공기관 사업의 모든 산출물은 결국 HWP/HWPX 한 폴더로 귀결된다. 사업계획서·기안문·결재문서·검토보고서·공문·회의록 — 전부 아래한글이다. 한컴오피스 라이선스가 없거나, 모바일에서 원격으로 작업할 때, 30개 동시 운용에서 본인이 직접 한컴을 못 띄울 때, HWP를 못 다루는 AI는 공공 사업장에서는 무용지물이다.

문제는 HWP가 DOCX와 다르다는 점이다. DOCX는 ZIP 기반 XML이라 unzip 해서 XML 한 줄 고치면 끝인데, HWP는 OLE 복합문서(바이너리) — pyhwp·olefile 같은 전용 파서 없이는 텍스트 한 글자도 못 읽는다. 그 위에 HWPX(XML 신형식)가 추가되면서 두 갈래로 갈라졌다. 두 포맷을 한 입구로 통일해서 다루는 능력이 공공 AX의 진입 장벽이다.

본인이 누적 운용 동안 부딪힌 가장 흔한 시나리오 세 가지: (1) 발주처가 HWP로 보낸 RFP를 분석해 제안서 초안 작성, (2) 본인이 만든 분석 결과를 발주처가 받아볼 HWP 양식으로 출력, (3) 매년 반복되는 100건 이상의 표준 기안문·공문 일괄 생성. 이 세 가지를 매번 손으로 하면 사람이 죽는다. 스킬화하면 "기안문 100개 만들어" 한 줄로 끝난다.

본인 사고가 여기에 박힌다 — "한국 공공 양식은 외부 자산이 아니라 본인 노하우다". 한 번 만들 때 양식 자산화까지 같이 박아놓아야, 다음 사업·다음 발주처에서도 그 자산이 자동으로 호출된다. SAL Grid 프로젝트 자동 감지 원리와 같다 — 환경(공공기관 발주처)이 감지되면 양식이 자동 적용되어야 한다.

핵심 개념

HWP vs HWPX 포맷 차이

항목 HWP (구) HWPX (신)
구조 OLE 복합문서 (바이너리) ZIP + XML
등장 한글 v5.0~ 한글 2014~
파서 pyhwp / olefile 표준 XML 파서
변환 호환성 보통 (LibreOffice 일부 깨짐) 우수 (DOCX와 유사 구조)
본인 권장 변환·읽기만 신규 생성 시 우선 사용

본인 운용은 단순하다 — 읽을 때는 둘 다 받고, 쓸 때는 HWPX로 만든 뒤 발주처가 원하면 한컴에서 HWP로 저장.

두 갈래 처리 경로

경로 A — 읽기·변환 (자동화 가능)

# HWP → 텍스트 (pyhwp)
hwp5txt 발주서.hwp > 발주서.txt

# HWP → HTML (구조 보존, 표·이미지 일부 보존)
hwp5html 발주서.hwp > 발주서.html

# HWP → PDF (LibreOffice headless, 레이아웃 우수)
soffice --headless --convert-to pdf 발주서.hwp

# HWPX → DOCX (LibreOffice, 호환성 가장 좋음)
soffice --headless --convert-to docx 발주서.hwpx

경로 B — 생성 (제약 있음)

"HWP 생성은 한컴오피스(유료)만 가능" — doc-generator-기본 §5-4

본인 우회 패턴: DOCX로 docx-js 생성 → 발주처가 한컴에서 열어 다른 이름으로 HWP 저장. 생성 단계에서 한글 폰트(Malgun Gothic)·여백·표 폭(WidthType.DXA)을 공공 표준에 맞춰두면 한컴에서 열어도 거의 그대로 나온다.

한국 공공 표준 양식 자산화

본인이 스킬로 박아놓은 양식 4종:

양식 용도 핵심 필드
기안문 내부 결재 제목·기안자·결재선·시행일·붙임
검토보고서 사업 검토 사업명·검토배경·현황·검토의견·결론
공문(시행문) 외부 발송 수신·참조·제목·본문·발신명의·시행번호
회의록 회의 결과 일시·장소·참석자·안건·결정사항·후속조치

각 양식은 ~/.claude/skills/공공양식-기본/templates/{기안문,검토보고서,공문,회의록}.docx 로 박아둔다(템플릿 자체는 DOCX, 발송 시 HWP로 변환). 한 번 박아두면 "이번 사업 검토보고서 작성" → 자동으로 검토보고서 템플릿이 호출되고, 사업명·일자만 채워 넣으면 끝난다.

변환 매트릭스 (본인 자주 쓰는 것만)

From → To 명령 본인 사용 빈도
HWP → TXT hwp5txt input.hwp > out.txt 매주 (RFP 분석)
HWP → PDF soffice --convert-to pdf input.hwp 매주 (배포본)
HWP → DOCX soffice --convert-to docx input.hwp 가끔 (역공학)
HWPX → PDF soffice --convert-to pdf input.hwpx 매월
DOCX → HWP (한컴 수동) 발주 시
MD → HWP MD→DOCX→(한컴) 보고서 작성 후

실전 사용법

시나리오 A — 발주처 RFP 분석 (5분 안에)

# Step 1: HWP를 텍스트로 추출
hwp5txt RFP_2026_공공AI사업.hwp > rfp.txt

# Step 2: Claude Code에 분석 의뢰
# "rfp.txt 읽고 사업 범위·기간·예산·핵심 요구사항 4표로 정리"

# Step 3: 산출물은 MD로 받아서 본인 Wiki에 적재

이 단계까지 가면 3시간 걸리던 RFP 1차 분석이 30분으로 단축된다. 본인 사례에서 검증. (측정: 본인 공공 AX RFP 분석 작업 종래 평균 소요 vs AI 도입 후 평균 소요 비교)

시나리오 B — 검토보고서 템플릿 호출 (한 줄)

사용자: "이 사업 검토보고서 작성해. 사업명: 'AI 챗봇 도입', 발주처: 'XX청'"

스킬이 templates/검토보고서.docx 를 자동 로드 → 8섹션(검토배경·현황·필요성·기대효과·소요예산·추진일정·리스크·결론) 골격에 본인 분석 내용 자동 채움 → DOCX 산출 → 한컴에서 열어 HWP 저장.

시나리오 C — 공문 100개 일괄 생성

# CSV: 수신처·제목·본문 100행
# 헤드리스 모드(#10)로 일괄 처리
import pandas as pd
from docx import Document

template = "templates/공문.docx"
df = pd.read_csv("발송리스트.csv")
for i, row in df.iterrows():
    doc = Document(template)
    # 수신/제목/본문 치환
    # ... (Malgun Gothic 폰트 유지)
    doc.save(f"공문_{i:03d}_{row['수신']}.docx")

100개 공문이 5분 안에 만들어진다. 한 건당 5분 걸리던 작업(8시간)이 5분으로 줄어든다.

자주 만나는 함정

증상 원인 해결
HWP 안 열림 pyhwp v5 미만 미지원 LibreOffice 시도
변환 후 글자 깨짐 폰트 미설치 Malgun Gothic 강제 적용
표가 깨짐 LibreOffice ↔ 한컴 차이 HWPX 우선 사용
HWP 생성 시도 실패 한컴 라이선스 필요 DOCX 생성 후 한컴 변환

KPI 강제

본인 스킬에 박아둔 검증 KPI: - 데이터 레이어: 텍스트 추출 시 RFP 본문 글자 수 ≥ 95% 보존 (측정: pyhwp/LibreOffice 추출 결과 글자 수 / 원본 한컴 본문 글자 수 비율) - 사용자 여정: 발주처 담당자가 한컴에서 열었을 때 (1) 폰트 유지 (2) 표 깨짐 없음 (3) 결재선 자동 표시 — 3개 모두 통과해야 Verified

"파일이 만들어졌다" 는 데이터 레이어 KPI일 뿐. 발주처가 실제로 열어서 결재 진행할 수 있어야 한다 — curl 200 ≠ 동작함 원칙이 여기에도 박혀 있다.

본인 운용 패턴

본인은 공공 사업 1건당 평균 HWP 30~50개를 다룬다. 30개 동시 운용에서 한 슬롯은 항상 "공공 양식 자산화 슬롯". 그 슬롯이 발주처에서 받은 새 양식을 자동으로 templates/ 폴더에 박아 넣고, 다음 사업에서 자동 호출되도록 SKILL.md에 반영한다.

ax-on.net 본인 사이트 가이드의 "공공 AX 진입 가이드" 페이지 핵심 자료가 바로 이 양식 자산. 누적 운용의 가장 단단한 자산 중 하나다.
