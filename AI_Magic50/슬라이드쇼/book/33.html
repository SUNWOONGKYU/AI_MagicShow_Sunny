SUNNY AI MAGIC 50 · #33

CLAUDE.md 잘 활용하기

Claude Code가 켤 때마다 먼저 읽는 사용자 운영 매뉴얼
G5 · 환경

한 줄 정의

CLAUDE.md는 Claude Code가 매 세션을 켤 때 가장 먼저 자동으로 읽는 사용자 지시 파일이다. 위치는 두 곳 — 전역(~/.claude/CLAUDE.md, 모든 프로젝트에 적용) + 프로젝트별(<project>/CLAUDE.md, 그 프로젝트만). 사용자가 매 새 세션마다 직접 천 번 말해야 했을 출력 포맷·도구 호출 화법·작업 방식·자동 발동 트리거·절차 규칙·쓸 수 있는 도구 목록·사용자 환경 정보를 한 파일에 모아둔다. 30개 인스턴스가 어느 디렉토리·어느 서브에이전트에서 작업하든 동일한 규칙·동일한 자동 발동을 갖게 만드는 사용자 운영 매뉴얼이다.

왜 이 노하우가 중요한가

Claude Code를 5개 이상 동시에 돌려본 사람은 곧 한 가지 사실을 깨닫는다. 같은 모델·같은 프롬프트라도 같은 결정을 내리지 않는다. A 인스턴스는 파일 경로를 한 줄로 길게 출력하고, B 인스턴스는 끊어서 출력한다. C 인스턴스는 자기가 만든 UI를 자기가 검증해 "Verified" 처리하고, D 인스턴스는 별도 검증을 거친다. 이 작은 분기가 30개 인스턴스에서 누적되면, 본인 한 사람이 "도대체 어느 결과를 신뢰해야 하는가"의 늪에 빠진다.

본인 4,000시간 누적에서 도달한 결론 — 운영 원칙은 입으로 말하는 한 흩어진다. 같은 사용자가 같은 요청을 30번 다르게 표현하기 때문이다. "버튼 클릭 테스트해줘", "실제로 동작하는지 확인해줘", "Verified 처리해줘" — 표현이 다르면 AI는 다른 검증 강도를 적용한다. 그래서 표현이 아닌 CLAUDE.md 파일이 필요하다. 모든 인스턴스가 세션 시작 시 자동으로 읽고, 그 안의 규칙을 사용자 발화보다 우선해 따르는 단 하나의 파일.

본인 ~/.claude/CLAUDE.md는 그래서 단순한 메모가 아니다. 일곱 개의 다층 가드가 들어 있다.

  1. 표시 규칙 가드 — 파일 경로 한 줄 출력 금지(폴더/파일 분리)
  2. 언어 운용 가드 — recall 호출을 "조용히" 사용(채팅창 노출 금지)
  3. UI 검증 가드 — curl 200 ≠ 동작함(브라우저 클릭 테스트 강제)
  4. 자동 감지 가드 — SAL_Grid_Dev_Suite/ 폴더 보이면 청룡 + MBO 자동 발동
  5. 멀티 페이즈 가드 — 3단계 이상 작업 시 PHASE 파일 강제 생성·체크
  6. 도구 카탈로그 가드 — 다큐킹앱 57개 스킬 목록 색인
  7. 모바일 전달 가드 — 결과는 G드라이브 .txt로 저장(원격 데스크탑 한계 우회)

이 일곱 개가 동시에 작동하면, 30개 인스턴스 어디에 들어가도 같은 답이 나오기 시작한다. CLAUDE.md가 표현 차이를 흡수하기 때문이다. "입력은 사람의 자연어, 실행 골격은 CLAUDE.md의 결정론" — 이 문장이 본인 CLAUDE.md 운용의 한 줄 요약이다.

핵심 개념

CLAUDE.md에 보통 적어두는 7가지

본인 운영 매뉴얼을 살펴보면 다음 7개 카테고리가 분명히 분리된다.

# 카테고리 CLAUDE.md에 적어두는 것 본인 CLAUDE.md의 실제 항목
1 출력 포맷 강제 Claude 답변의 모양 통일 파일 경로 폴더/파일 분리
2 도구 호출 화법 메타 발화 금지 recall 침묵 원칙
3 작업 방식 규칙 "이렇게 일해라"의 강제 UI 검증 — curl 200 ≠ 동작함
4 자동 발동 트리거 폴더·키워드 보면 알아서 발동 SAL Grid 폴더 → 청룡+MBO 자동
5 절차 규칙 작업 진행 흐름 강제 3단계 이상 → PHASE 파일 필수
6 도구 카탈로그 "쓸 수 있는 무기 목록" 통보 다큐킹앱 57개 스킬
7 사용자 환경 정보 본인 작업 환경 특이점 모바일 원격접속 → G드라이브 .txt 전달

이 7개가 본인 CLAUDE.md 한 파일 안에 동시에 들어 있다. 매 새 세션마다 사용자가 새로 가르칠 필요 없게 만드는 구조다.

CLAUDE.md의 위치 — 단일 출처(SSOT)

본인 운영 매뉴얼은 정확히 한 곳에 있다.

📁 ~/.claude/   (Windows 실경로: C:\Users\home\.claude\)
📄 CLAUDE.md

이 한 파일이 모든 디렉토리·모든 인스턴스·모든 세션의 첫 페이지로 자동 로드된다. 프로젝트별 <프로젝트>/.claude/CLAUDE.md는 이 전역 매뉴얼을 상속받아 프로젝트 고유 규칙만 추가한다. SAL Grid Dev Suite의 MBO_SPEC_VERSION 태그처럼, CLAUDE.md 간 정합성도 pre-commit 훅(scripts/verify-mbo-sync.js)이 자동 검증한다.

7대 가드 상세

가드 1 — 표시 규칙 (모바일 친화)

📁 zz_KingFolder/KingDesk2_DOC/
📄 24000_클코_킹워크지침_인젝션_프로세스_기본정책.md

긴 절대경로를 한 줄로 쓰지 않는다. 본인이 폰에서 원격 데스크탑으로 접속할 때 화면 폭이 좁아 한 줄로 출력하면 줄바꿈이 깨진다. 폴더와 파일명을 분리하면 "폴더 먼저 찾고 그 안에서 파일 클릭"의 흐름이 그대로 살아난다. 이건 미적 취향이 아니라 모바일 운용 환경에서 도출된 인체공학 규칙이다.

가드 2 — 언어 운용 (recall 침묵 원칙)

recall은 본인의 장기기억 검색 도구다. CLAUDE.md는 명시한다 — "recall 호출 사실을 굳이 언급하지 않는다." "기억을 찾아보겠습니다", "recall에서 찾았는데" 같은 메타 발화 금지. 결과는 자연스럽게 응답에 녹여라. 이 규칙은 사용자 체감 응답 속도를 30~40% 끌어올린다 — 도구 호출이 보이지 않으니 "AI가 그냥 알고 있는 것"으로 인지되기 때문이다. 작은 규칙처럼 보이지만 신뢰도와 직결된다.

가드 3 — UI 검증 철칙 (curl 200 ≠ 동작함)

이게 본인 운영 매뉴얼에서 가장 비싼 교훈이다. 한 배포 사건에서 curl로 200 OK 받고 Verified 처리했지만, 실제 브라우저에서 보니:

  • "시작하기"·"더 알아보기" 버튼 → href 없어 클릭 무반응
  • 4개 은하 원 → <div>로 만들어 클릭 불가
  • "View All" → 존재하지 않는 /rankings로 404
  • 랭킹 카드 → /skills/${uuid} 경로·파라미터 전부 틀림

이 한 사건이 5개 파일에 동시 반영됐다 — mbo-코어5/SKILL.md, 청룡-sal-grid-dev/SKILL.md, SAL_Grid_Dev_Suite/.claude/CLAUDE.md, rules/06_verification.md, rules/07_task-crud.md. 하나의 사고가 다섯 곳의 운영 매뉴얼을 동시에 갱신하는 리플렉션 체인 — 이게 CLAUDE.md가 살아 있다는 증거다. CLAUDE.md는 한 번 쓰고 끝나는 문서가 아니라, 사고가 발생할 때마다 자라는 유기체다.

가드 4 — SAL Grid 자동 감지 (사용자 발화 없이 발동)

가장 영리한 가드. CLAUDE.md에 다음과 같이 적혀 있다.

작업 디렉토리에 SAL_Grid_Dev_Suite/ 폴더가 존재하거나 경로에 Process/S0_Project-SAL-Grid_생성/이 보이면, 별도 지시 없이도 청룡 스킬 + mbo-코어5가 자동 적용된다.

사용자가 "청룡 써", "MBO 해" 라고 말하지 않아도 발동. 이 한 줄이 인스턴스 간 행동 차이를 0으로 만든다. 본인이 새 컴퓨터에서 새 인스턴스를 띄워도, 전역 CLAUDE.md만 동일하면 SAL Grid 프로젝트에선 동일한 자동화가 즉시 작동한다. 표현은 환경에 의존하지 않는다 — 폴더 구조만 의존한다.

추가로 Stage 진입 키워드("S2 실행", "다음 Stage", "Stage Gate 통과")를 감지하면 MBO 제시 → PO 승인 → Task 실행 순서를 강제한다. scripts/task-guard.js(Tier 3)가 MBO 미승인 상태의 Task status 전이를 물리적으로 차단한다 — CLAUDE.md가 코드 가드와 짝을 이루는 지점.

가드 5 — 멀티 페이즈 행동 규칙

3단계 이상 작업 시 강제 흐름.

zz_KingFolder/_TalkTodoPlan/2026_05_06__21.30_PHASE_본문일괄작성.md
  • 규칙 1 — 시작 전 PHASE 파일 생성
  • 규칙 2 — 매 Phase 시작 전 파일 Read(컴팩션·세션 변경 시 상태 복원)
  • 규칙 3 — Phase 완료 즉시 [ ] → [x] 갱신
  • 규칙 4 — [ ]가 남아 있는 Phase는 미완료로 간주

마지막 한 줄이 핵심 — "'했던 것 같다'는 기억은 신뢰하지 마라. 파일이 진실이다." AI의 환각, 본인의 착각을 동시에 차단하는 단일 진실원천 원칙.

가드 6 — 도구 카탈로그 (다큐킹앱 57개 스킬 색인)

CLAUDE.md 안에 워크플로우 15개 + 도구 42개 = 57개 스킬 사용 시점이 표로 정리돼 있다. /feature-development, /full-review, /smart-fix, /tdd-cycle부터 /cost-optimize까지. 새 인스턴스가 CLAUDE.md를 읽는 즉시 본인이 보유한 무기 목록 전체를 알고 시작한다. 모르고 새로 만드는 일이 사라진다.

가드 7 — 모바일 전달 (G드라이브 .txt 자동화)

긴 명령어·URL·요약은 항상 클라우드 동기화 폴더(Google 드라이브/OneDrive 등)에 .txt로 떨어뜨린다.

📁 <클라우드 동기화 폴더>/<프로젝트>/
📄 2026_05_06__결과_URL.txt

폰에서 원격 데스크탑으로 들어갈 때, 화면 텍스트는 복사가 안 되지만 클라우드 동기화 앱은 즉시 열린다. 이 한 줄 가드가 누적 운용에서 가장 자주 호출되는 규칙이다.

CLAUDE.md와 스킬의 짝 — 청룡·MBO 자동 호출 메커니즘

CLAUDE.md가 "자동 감지" 가드에서 호출하는 두 스킬:

호출되는 스킬 역할 트리거
청룡-sal-grid-dev Stage 실행 6단계, Verification 분리, Stage Gate 5단계 리포트 SAL_Grid_Dev_Suite/ 폴더 감지
mbo-코어5 Stage 진입 전 목표 정의·PO 승인 플로우·결과 보고 "S{N} 실행" 등 키워드 감지

CLAUDE.md가 두 스킬을 짝으로 묶는다. SAL Grid가 실행 골격, MBO가 합의 골격. 둘은 분리해 쓰지 않는다(#8·#2 참고).

한국 공공 문서 양식 적용 응용

본인 CLAUDE.md의 다층 활용 중 한 갈래는 한국 공공 문서 양식 통합이다. CLAUDE.md의 모바일 전달 가드는 G:\내 드라이브\ 동기화 폴더 활용을 명시하고, 이 폴더에 한국 공공 양식(HWP/HWPX, PDF 보고서)을 떨어뜨리면 본인이 폰의 Google 드라이브 앱에서 즉시 확인할 수 있다. CLAUDE.md + 다큐킹 스킬(/doc-generate) + doc-generator-기본 스킬이 한 흐름으로 묶이며, 결과는 한국식 공공 양식으로 출력 — 한국 공공 발주 환경 특유의 "HWP 의존성"을 CLAUDE.md 한 줄로 흡수한다.

실전 사용법

1단계 — CLAUDE.md 초안 작성

빈 ~/.claude/CLAUDE.md에 4개 섹션부터 시작.

  1. 표시 규칙 — 파일 경로 폴더/파일 분리(모바일 친화)
  2. 언어 운용 — 도구 호출 침묵 원칙
  3. UI 검증 — curl 200 ≠ 동작함
  4. 자동 발동 — 폴더 감지 시 자동 적용할 스킬 목록

이 4개가 최소 골격. 나머지는 사고가 발생할 때마다 추가한다.

2단계 — HTML 주석 마커로 구조화

<!-- FILE_PATH_DISPLAY_START -->
## 파일 경로 표시 규칙
...
<!-- FILE_PATH_DISPLAY_END -->

<!-- RECALL_GUIDE_START -->
## recall 사용 지침
...
<!-- RECALL_GUIDE_END -->

마커가 있으면 자동화 스크립트가 섹션별 추출·갱신을 할 수 있다. 본인 CLAUDE.md는 6개 마커로 분할돼 있어, verify-mbo-sync.js가 청룡·mbo-코어5 SKILL.md와의 정합성을 마커 단위로 검증한다.

3단계 — 사고 발생 시 리플렉션 체인 생성

새 사고가 터지면 반드시 다섯 곳에 동시 반영한다.

1. ~/.claude/CLAUDE.md (전역 매뉴얼 본문)
2. ~/.claude/skills/<관련 스킬>/SKILL.md
3. <프로젝트>/.claude/CLAUDE.md
4. <프로젝트>/.claude/rules/<번호>_<주제>.md
5. SAL Grid의 grid_records JSON (해당 Stage Gate 사고 기록)

한 곳만 고치면 다인스턴스 중 CLAUDE.md만 읽고 들어온 일부가 옛 규칙으로 작동한다. 다섯 곳을 동시에 고쳐야 운영 매뉴얼이 생물처럼 진화한다. "curl 200 ≠ 동작함" 사고가 정확히 이 5단 동시 반영 패턴의 첫 사례다.

4단계 — pre-commit 훅으로 정합성 강제

# .git/hooks/pre-commit (또는 husky)
node scripts/verify-mbo-sync.js   # MBO_SPEC_VERSION 일치 검증
node scripts/sal-guard.js         # TASK_PLAN ↔ grid_records 정합성
node scripts/task-guard.js        # MBO 미승인 Task status 전이 차단(Tier 3)

CLAUDE.md가 종이호랑이가 되지 않는 마지막 방어선. 사람이 잊어도 시스템이 차단한다.

5단계 — 자동 발동 키워드 풍부화

처음엔 "S2 실행" 같은 명시적 키워드만 트리거하지만, 운용하면서 "다음 단계로 갈게", "이제 백엔드", "Stage 4 들어간다" 같은 자연어 표현을 발견하면 CLAUDE.md에 추가한다. 키워드 풍부화가 곧 본인의 자연어가 CLAUDE.md 트리거로 흡수되는 과정이다. 6개월 운용 끝에 본인은 "청룡 써" 라고 말한 적이 손에 꼽는다 — 폴더 구조와 키워드만으로 자동 발동되기 때문이다.

6단계 — 모바일 전달 자동화

긴 명령어·URL·요약은 항상 클라우드 동기화 폴더(Google 드라이브/OneDrive 등)에 .txt로 떨어뜨린다.

📁 <클라우드 동기화 폴더>/<프로젝트>/
📄 2026_05_06__결과_URL.txt

본인 운용 패턴

본인 CLAUDE.md의 가장 큰 가치는 "이 파일을 잃어버리면 본인 운영이 즉시 망가진다" 라는 명제다. 그래서 CLAUDE.md는 클라우드 동기화 백업과 GitHub private repo 양쪽에 이중 동기화돼 있고, 새 컴퓨터 셋업 첫 30분이 정확히 이 CLAUDE.md를 복원하는 시간이다(#20 C드라이브+G드라이브 백업과 짝). CLAUDE.md 복원이 끝나는 순간, 새 컴퓨터에서도 "청룡 자동 발동, MBO 자동 발동, UI 클릭 검증 강제, 모바일 전달 자동화"가 즉시 살아난다.

또 하나 — 본인 CLAUDE.md는 30개 동시 운용의 합의 골격이다. 인스턴스마다 다른 답을 내지 않게 만드는 것은 모델의 결정론이 아니라, 모든 인스턴스가 같은 CLAUDE.md를 먼저 읽는다는 사실이다. 같은 CLAUDE.md + 같은 폴더 구조 + 같은 SAL Grid → 같은 결정. 이 등식이 성립할 때 비로소 "1인 30군"이 작동한다.
