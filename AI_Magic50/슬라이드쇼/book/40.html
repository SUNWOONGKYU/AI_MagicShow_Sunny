SUNNY AI MAGIC 50 · #40

개발은 C드라이브에서, 백업은 G드라이브에 동기화

속도와 효율은 C드라이브 SSD, 안전과 범용성은 G드라이브 동기화
G5 · 환경 C타입

한 줄 정의

작업 폴더를 C드라이브(SSD, 빠른 I/O) + G드라이브(Google Drive 동기화, 자동 클라우드 백업) 이중화해 속도와 안전성·모바일 접근성을 동시에 확보하는 본인 표준 환경.

왜 이 노하우가 중요한가

Claude Code는 파일을 끊임없이 쓰고 읽는다. 빌드·테스트·git은 C드라이브가 빠르고, 결과물 공유·모바일 확인·재해 복구는 G드라이브가 안전하다. 한쪽만 쓰면 양쪽 다 잃는다 — C 단독은 디스크 고장 시 누적 자산이 증발하고, G 단독은 Google Drive 동기화 지연으로 git 작업이 깨진다.

본인은 모바일에서 원격 데스크탑으로 자주 접속하므로 G드라이브 경로가 곧 폰의 Google Drive 앱과 연결된다는 점이 결정적이다. 작업 결과 URL을 G드라이브 .txt로 저장하면 폰에서 즉시 복사 가능 — 이것이 30개 동시 운용(#31)의 외부 출력 채널이다.

핵심 개념

이중화 구조:

폴더 위치 용도
작업본 C:\Users\home\프로젝트\ 빌드·테스트·git 일상 작업
백업·공유본 G:\내 드라이브\333_자료공유폴더\ 자동 클라우드 동기화, 모바일 접근, 공유
글로벌 자산 C:\Users\home\.claude\ (스킬·CLAUDE.md) 별도 git 백업

원칙: - 빌드 산물(node_modules, .next)은 C에만 — G로 동기화하면 Google Drive가 수십만 파일에 질식 - git 저장소는 C에서 운영 — 동기화 충돌 방지 - 결과물(MD, HTML, 영상)은 G에 사본 또는 직접 작성 - 사용자에게 전달할 URL·로그는 G의 .txt 파일로 저장

실전 사용법

1단계 — Google Drive 데스크탑 클라이언트 설치, G:\내 드라이브\ 마운트 확인.

2단계 — 프로젝트 분류: - 개발 프로젝트 → C드라이브에서 작업, git remote(GitHub)가 1차 백업 - 자료·문서 프로젝트 → G드라이브에 직접 작성 (본 AI Magic 50선이 그 예)

3단계 — .gitignore에 node_modules/, dist/, .next/ 등 등록해 git 백업 시 빌드 산물 제외.

4단계 — 중요 산출물은 작업 종료 시 G로 복사 또는 git push. 본인은 매일 작업 종료 시 G:\내 드라이브\333_자료공유폴더\Sunny_Magic_Show\ 같은 도메인별 폴더에 결과물 사본을 떨어뜨린다.

5단계 — 모바일 전달은 G드라이브 .txt — 배포 URL, 명령어, 요약은 G:\내 드라이브\프로젝트\결과_URL_YYYYMMDD.txt 형태로 저장. 폰 Google Drive 앱에서 즉시 복사.

금지 사항: G드라이브 안에서 npm install 같은 대량 파일 생성 작업. 동기화가 막히고 충돌 파일이 양산된다.

일일 점검 체크리스트: - [ ] G드라이브 동기화 상태 정상 (트레이 아이콘 초록) - [ ] 작업 종료 시 핵심 산출물 G로 사본 또는 git push 완료 - [ ] .gitignore에 node_modules/, dist/, .next/ 등록 확인 - [ ] 모바일 전달용 결과 .txt 파일 생성·날짜 표기
