SUNNY AI MAGIC 50 · #14

군대의 소대 편제방식을 활용한 대규모의 AI 투입하기

소대장·분대장·분대원·용병·스킬로 구성된 조직 투입
G3 · 실행 방법 📜 특허 10-2026-0041235

한 줄 정의

대규모 AI 운용을 평면적(flat) 에이전트 풀이 아니라 소대장 1 + N개 분대(분대장 + 정규병 12 + 예비병 3) + 용병 풀 4 + 21 Skills 의 군 조직 편제로 구조화하여, 통신 경로를 O(n²) → O(n)으로 줄이고 모델 등급을 계층별로 차등 배치해 이중(곱셈적) 비용 절감을 달성하는 운용 방식. 본인 글로벌 스킬 백호-platoon-formation(SKILL.md)이 이 편제의 표준이며, 별도 특허(Platoon_Formation_Patent/)로 출원 준비 중이다.

왜 이 노하우가 중요한가

Claude Code Agent Teams(CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1)를 활성화하면 팀리더 + 팀메이트들이 독립 컨텍스트 윈도우로 직접 통신할 수 있다. 하지만 공식 권장은 3~5개 팀메이트다 (#39 참조). 이걸 6개·12개·44개로 늘리면 통신 경로가 n(n-1)/2 로 폭증한다. 평면 구조 42개 에이전트 = 861개 통신 경로. 토큰 비용·지연·컨텍스트 오염이 곱셈적으로 누적되어 5개만 돌려도 무너진다. 본인이 5번 무너뜨린 이력이 있다.

군대의 소대 편제는 이를 수천 년에 걸쳐 검증된 계층 구조로 푼다. 소대장은 분대장만, 분대장은 자기 분대원만 본다. 분대원끼리는 통신하지 않고 분대장끼리만 수평 교신을 허용한다. 44명 A형 1소대 통신 경로 ≈ 45개(소대장↔분대장 3 + 분대장 간 수평 3 + 각 분대 내 분대장↔정규병 12×3 = 3 + 36 + 3 + 용병 호출 3 ≈ 45), 같은 44명을 평면 구조로 묶을 때의 946경로(44×43/2) 대비 약 95.2% 감소. 70명 B형 99.0%, 420명 10소대 99.5%, 4,200명 100소대 99.95% 감소. 토큰·비용·지연·컨텍스트 오염이 비례 감소한다. 제1 절감.

여기에 제2 절감이 곱해진다. 평면 구조는 모든 에이전트에 Opus를 박는다. 소대 편제는 소대장=Opus / 분대장=Sonnet / 정규병+예비병=Haiku 위주 로 계층별 최적 등급을 배치, 단가 차이만으로 약 94.7% 비용 절감. 두 절감이 곱셈적으로 결합되어 개별 절감의 합산을 초과한다. 백호 SKILL의 "이중 결합(곱셈적)" 단락이 본 발명의 정량 근거이며, Platoon_Formation_Patent/ 청구항의 진보성 주장이다.

누적 운용에서 도달한 결론 — "대규모 AI 동시 운용은 단일 인스턴스를 잘 다루는 것보다 다수를 어떻게 묶는지가 90%다." SAL Grid가 작업의 위치 골격이라면, 소대 편제는 에이전트의 위치 골격이다. 둘은 한 쌍이고, 둘 모두 본인 특허다.

핵심 개념

편제 공식

HQ(1) + N Squads × 13(Leader+12 정규병) + 4 Mercenaries(Shared) + 예비병 N×3 별도

A형(기본) N=3 → 44명 (HQ 1 + 3×13 + 용병 4 = 44 / 예비병 9 별도) B형(확장) N=5 → 70명 (HQ 1 + 5×13 + 용병 4 = 70 / 예비병 15 별도) C형(지정) N=6+ → 상한 없음

HQ — 소대장 1명 (Opus)

오케스트레이터·전략적 의사결정·직접 코딩 최소화. 챗봇 UI(CPC 통한 ax-on.net)가 직접 연결된다. 책무: 임무 분해 / 분대별 업무·모델·권한 통합 배정 / 분대장 간 충돌 자율 중재 / 결과 종합·워크로그 저장 / 지휘관 보고. "병력을 동원하라" 가 소대장 행동강령 첫 줄이다.

분대 — NATO 호출부호로 구조화

Alpha(설계/분석) · Bravo(개발/구현) · Charlie(문서/QA) · Delta(보안/인프라, 확장) · Echo(성능/최적화, 확장) · Foxtrot~(지정 시). NATO 음성 알파벳 순서. 호출부호만 듣고도 누구의 보고인지 즉시 식별 가능. 기본 역할은 지휘관 미지정 시의 디폴트일 뿐, 임무 부여 시 동적 재배정.

정규병 12종 + 예비병 3종 (각 분대 공통)

분대마다 12명 정규병이 표준 배치된다 — frontend-developer · ux-ui-designer · api-developer · backend-developer · database-developer · code-reviewer · test-runner(Haiku) · security-specialist · devops · debugger · doc-writer(Haiku) · content-copy(Haiku). 정원 외 예비병 3종(qa-specialist · refactoring-specialist · performance-optimizer)은 지원 임무 시 분대장이 호출한다.

용병 풀 4명 (공유 자산)

소대 소속이 아닌 공유 풀 — Codex(OpenAI, 새 프로젝트 스캐폴딩) · Gemini(Google, 200만 토큰 컨텍스트) · Grok(xAI, 빠른 프로토타이핑·실시간 검색) · Perplexity(실시간 웹 리서치). 소대장·분대장 누구나 호출. 외부 CLI headless 모드 또는 MCP. "Claude Code가 오케스트레이터, 다른 CLI들은 특화 실행 도구" — #22의 멀티 CLI 패턴이 흡수되어 있다.

21 Skills (전 계층 공용)

소대장·분대장·서브에이전트가 자율적으로 장착한다. 6 그룹 — 프로젝트 관리(SAL Grid Dev) / 팀 편성(deploy-subagent·deploy-skill·find-skills) / 개발&인프라(api-builder·ui-ux-builder·db-schema·cicd-setup) / 콘텐츠&생성(slideshow-web·youtube-generate·create-image·doc-generator) / 품질&보안(review-evaluate·security-audit·troubleshoot·e2e-test·api-test·performance-check) / CPC 인프라(cpc-setup·cpc-add-project·cpc-engage). 분대원이 임무를 분석해 자율 선택·장착한다.

통신 구조

수직(소대장→분대장→분대원, SendMessage)과 수평(분대장↔분대장 직접 교신) + 외부(용병 풀 호출, Bash CLI/MCP). 분대장 간 직접 교신은 허용, 단 분대원끼리는 직접 통신 금지 — 정규병끼리 메시지 주고받게 두면 컨텍스트가 곧장 오염된다.

지휘관 상호작용 3회 — 전체 작전에서

횟수 시점 용도
개입 ① Phase 1.5 (S15) 임무 부여 + 분대 수 결정
개입 ② Phase 5.5 (S60) 작전 개시 승인
개입 ③ Phase 7 (S80) 해산 승인

이 3회 외에는 지휘관에게 보고·질문·확인을 일체 하지 않는다. 분대장 블로커는 소대장이 자율 판단, 분대장 간 의견 충돌도 소대장이 자율 중재. 지휘관이 모바일 원격으로 작전 모니터링만 할 수 있는 구조.

실전 사용법

Phase 0~7 표준 사이클

0. 운영 모드 선택 (단일 / 병렬 — tmux로 N소대 동시 전개)
1. 소대 편성 (TeamCreate + Alpha·Bravo·Charlie 병렬 스폰)
1.5 ──[개입 ①]── 임무 부여 + 분대 수 결정 (A/B/C형)
1.7 작업 분해 + 업무·모델·권한 통합 배정
2. 용병 투입 전략
3. 스킬 연동
4. 스킬 자율 장착
5. 작전 대기 상태 보고
5.5 ──[개입 ②]── 작전 개시 승인
6. 임무 수행 (병렬 처리, 실패 시 3단계 대응)
6.3 SAL Grid 반영 의무
6.5 결과 종합 보고서 작성 + 워크로그 저장
7. ──[개입 ③]── 해산 승인 → 즉시 TeamDelete

S60(작전 개시 승인) 1회 승인이 전체 단계를 포괄한다. 임무가 검토→수정→배포 다단계여도 중간 승인을 추가로 요구하지 않는다 — 소대장 자율 판단.

모델 등급 선정 — 하향 우선 원칙

소대장이 임무 성격·난이도·비용을 종합 고려한다 — 고수준 추론은 Opus, 표준 추론은 Sonnet(디폴트), 정형 반복은 Haiku. 동일 품질 가능 시 하위 등급 우선. 본인 운용 사례 — B형 소대(70+15명) 투입하면서 Opus는 소대장 1개에 한정, 분대장 5명 = Sonnet, 정규병 60명 = Haiku 36 + Sonnet 24. 평면 구조 대비 API 비용 약 90% 절감 실측 (운용 청구서 기준, 평면 Opus-only 시뮬레이션 대비).

도구 권한 + 통합 배정

분대장에게 임무 배정 시 "업무·모델·권한을 한 번에 통합 지정". 최소 권한 원칙 — 조사·분석은 Read만, 구현·수정은 Read+Write+Bash, 팀 관리는 +Agent. 분대장이 분대원에게 위임할 때도 동일.

SAL Grid 반영 의무 + 워크로그 저장

Phase 6.3 — 코드를 수정하면 반드시 SAL Grid에 기록. 예외 없음. "SAL Grid에 반영 없이 코드만 수정한 작업은 미완료로 간주" (글로벌 CLAUDE.md 헌법과 동일). Phase 6.5 — 해산 직전 분대 보고를 수집·교차검증·종합한 뒤 {프로젝트루트}/worklog/{YYYY-MM-DD}_{HH-MM}_{임무명}.md로 영구 저장. 컨텍스트 압축·세션 종료에 무관하게 보존.

병렬 소대 운영 (tmux)

복수 프로젝트 동시 진행 시 tmux N패널 분할 → 각 패널 winpty claude.cmd → /platoon-formation [단일] 선택. 외출 시 폰에서 Termius로 SSH 접속 + tmux attach -t multi-platoon — Ctrl+B로 순회·줌. #31(5컴퓨터 30개 운용)와 결합되면 다중 머신 × 다중 소대가 된다.

자주 빠지는 함정

  1. A형부터 시작. 6개 이상(C형)은 Rate Limit·토큰 비용·조율 오버헤드 별도 검토.
  2. run_in_background: false 필수. 백그라운드 스폰은 Write 권한 차단. Alpha·Bravo·Charlie를 한 메시지에서 동시 호출.
  3. 소대장이 직접 코딩하면 평면 구조로 회귀. "병력을 동원하라" 를 프롬프트 첫 줄에.
  4. 자기 검증 금지. 분대 A 산출물을 분대 A가 검증하면 안 된다. "curl 200 ≠ 동작함" 의 교훈.

KPI

  • 편제 규모: 44명(A형) / 70명(B형) / 상한 없음(C형)
  • 통신 경로 감소율: 평면 대비 약 95.2%(44명, A형) ~ 99.95%(4,200명, 100소대) (산식: 평면 N(N-1)/2 vs 계층 (분대 내부 + 분대장→소대장) 비교)
  • 모델 단가 비용 절감: 약 94.7% (Opus 1 + Sonnet N + Haiku 12N 비율) (측정: Anthropic 공식 모델 단가표 입력 토큰 기준 — Opus 4 / Sonnet 4 / Haiku 4.5 비교, 동일 임무 토큰 가정)
  • 이중 곱셈 효과: 통신 절감(메시지 수) × 모델 단가 절감(메시지당 비용) = 평면 Opus-only 대비 총비용 99% 이상 절감 실측 (잔여 비용 1% 미만) (측정: 본인 누적 운용 청구서 vs 평면 Opus-only 시뮬레이션)
  • 지휘관 상호작용 횟수: 정확히 3회 (그 외 일체 금지)
  • 소대 편성 시각: A형 기본 3명 병렬 스폰 → idle 진입까지 30~60초
  • 워크로그 저장률: 100% (Phase 6.5 강제, 컨텍스트 압축 대비)
  • SAL Grid 반영률: 100% (Phase 6.3 강제, 미반영 = 미완료)
