SUNNY AI MAGIC 50 · #41

피크타임 사용시간(저녁 11시~새벽 3시) 피하기

큰 작업은 가급적 지양 — Pro/Max 한도는 풀렸지만 글로벌 트래픽은 별개
G5 · 환경 C타입

한 줄 정의

본인 누적 운용에서 도출된 응답 지연·Rate Limit 도달이 가장 빈번한 시간대(저녁 11시~새벽 3시 KST) 를 의식적으로 회피하고, 그 시간을 헤드리스 자동화·인간 작업으로 돌리는 시간대 운용 노하우.

왜 이 노하우가 중요한가

Anthropic 인프라는 글로벌 트래픽 분포에 따라 한국 기준 야간(미국 동부 오전 ~ 이른 오후)이 가장 붐빈다. Anthropic 공식 정의로도 Peak Hours = PT 5:00~11:00 AM (= KST 21시~새벽 4시, 서머타임 ±1h)으로 본문 범위와 거의 일치. 같은 작업이 새벽 1시에는 30초 응답, 오전 6시에는 5초 응답으로 차이가 난다. 30개 동시 운용(#31) 시 응답 지연은 단순 누적이 아니라 분대장 inbox 막힘 → 분대원 대기 → 전체 정체로 연쇄된다.

7일 Rate Limit(#36 HUD LINE2 7d 막대)도 피크타임에 빠르게 차오른다. 같은 토큰을 써도 시간대를 바꾸면 체감 비용·체감 속도가 다르다는 것이 누적 학습의 결론.

2026-05-06 정책 변경 주의: Anthropic이 Claude Code의 Pro/Max 플랜에 한해 peak-hour reduction(피크 시간대 5시간 한도 가속 소모)을 폐지했다. 즉 Pro/Max 사용자는 피크타임에도 한도 측면 불이익이 사라졌다. 다만 (a) API 직접 호출(Tier 1~4), (b) Team 플랜, (c) 응답 지연·latency 자체는 여전히 글로벌 트래픽에 영향을 받으므로, 본 시간대 회피 노하우는 속도·안정성 관점에서 유효하다.

핵심 개념

본인 시간대 분류 (KST 기준):

시간대 등급 운용
새벽 4시~오전 9시 A (최적) 큰 작업·SAL Grid Stage 실행·30개 운용
오전 9시~오후 6시 B (양호) 일반 작업·페어 워크
오후 6시~밤 11시 C (혼잡 시작) 단일 인스턴스 가벼운 작업
밤 11시~새벽 3시 D (회피) 헤드리스 배치만, 인간은 이탈

회피 전략 3종: 1. 시간 시프트 — 큰 작업을 오전으로 이동 2. 헤드리스 외주 — 피크타임은 claude -p(#10)로 무인 운영, 결과만 다음날 확인 3. 모델 다운그레이드 — 피크타임 작업은 #34 /model haiku로 부하 최소화

실전 사용법

1단계 — 본인 일주일 시간대별 응답 시간 로그 수집. #36 HUD에 응답 지연 시각화하면 통계가 자연스럽게 쌓인다.

2단계 — 큰 작업·SAL Grid Stage 실행은 새벽 4~9시 슬롯에 예약. 본인은 이 시간대에 30개 인스턴스를 띄워 하루 분량을 끝낸다.

3단계 — 피크타임은 헤드리스 배치(#10) 로 전환. claude -p "작업 지시" 셸 명령을 cron에 걸어 무인 운영. 사람은 자고, AI만 일한다.

4단계 — 피크타임에 꼭 작업해야 한다면 모델을 Haiku로 강등(#34), 호출 빈도 절반, 컨텍스트 50% 이하 유지(#17) 의 3중 절제.

5단계 — 7일 Rate Limit 80% 도달 시(#36 HUD LINE2 7d) 즉시 작업 중단·다음 리셋까지 헤드리스만. 무리하면 다음 날 작업이 막힌다.

KPI 예시: 피크타임 호출 비중 50% → 15%, 평균 응답 시간 12s → 4s, 7d Rate 도달 횟수 주 3회 → 0회. ※ 위 KPI는 본인 누적 운용에서 #36 HUD LINE2 응답 지연·Rate Limit 로그를 기준으로 산출한 자기 측정치.

시간대 운용 체크리스트: - [ ] 큰 작업·SAL Grid Stage는 새벽 4~9시(A등급) 슬롯 예약 - [ ] 밤 11시~새벽 3시(D등급)는 헤드리스 배치(#10)만, 인간은 이탈 - [ ] 피크타임 작업 시 /model haiku + 호출 빈도 절반 + 컨텍스트 50% 이하 3중 절제 - [ ] 7d Rate 80% 도달 시 즉시 중단
