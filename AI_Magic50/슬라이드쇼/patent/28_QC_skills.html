SUNNY AI MAGIC · #28

4종 품질관리 스킬 (QC) — 3 평가 + 1 디버깅

작업결과물을 수시로 검증·개선하는 4개 스킬 — 가벼움(점수 채점)부터 무거움(다차원 진단)까지 위계가 다른 도구들의 조합
🛠 Skills: /review-evaluate · /pro-persona-debate · /주작-sal-da · /5times-debug-loop

📌 핵심 정의

AI 작업물에 대해 "다 됐다"를 그대로 믿지 않고, 4종 품질관리 스킬을 위계적으로 운용하여 완성도를 올린다. 평가 3종은 가벼움→무거움 순으로 review-evaluate(점수 채점) → pro-persona-debate(다관점 토론) → 주작-sal-da(다차원 진단·감사). 그리고 디버깅 1종은 5times-debug-loop(반복 박살). 본 4종은 특허 출원 대상(SDA Recommendation V9 — 만장일치 97.6점)인 자동 등급 부여 체계의 실행 도구이기도 하다.

🏗 4종 위계 — 가벼움 → 무거움

🎯 4종 스킬 상세

평가 1 · 가벼움

/review-evaluate-코어1

점수 채점 · 자기수렴 100점 도달까지 최대 10회 순환
  • 파일 타입별 전문 리뷰어 (Code/Document/Report)
  • Cross Validator로 자기평가 편향 차단
  • 루브릭 5~6기준 × 15~20점 = 100점
  • Phase 1.5 사양-구현 대조 (Spec-Code Alignment)
  • 명시적 증상 → /5times-debug-loop 위임
위치: QC 평가 3종 중 1번 · 단일 파일~디렉토리 검수
평가 2 · 중간

/pro-persona-debate-코어6

3+ 전문가 페르소나 + Devil's Advocate 토론
  • 다관점 검증 — 단일 LLM 편향 차단
  • Devil's Advocate 필수 참여 (반대측 논거)
  • 의사결정 정당화 + 합의안 도출
  • 특허 #02 (BuzzLab) 기반 다중 LLM 다차원 발언 ID
위치: QC 평가 3종 중 2번 · 정책·아키텍처 의사결정 검증
평가 3 · 무거움

/주작-sal-da

다차원 진단·감사 · 실측 + 시스템 등급/리포트 품질 분리
  • P0 런타임 베이스라인 필수 (빌드·서빙·스모크·스키마)
  • SAL Grid 3D 좌표로 산출물 분해
  • 20개 속성 6개 그룹 × Stage별 진단
  • 시스템 등급(X/10)과 리포트 품질(Y/100) 분리 표기
  • RuntimeFailFlag · Deferred Verdict로 결함 은닉 차단
위치: QC 평가 3종 중 3번 · 납품 전 최종 감사 · 특허 출원
디버깅 · 박살

/5times-debug-loop-코어3

5회 반복 디버깅 — 근본 원인 추적
  • 증상 → 가설 → 시도 → 결과 → 학습 사이클
  • review-evaluate · 주작-sal-da가 위임하는 도구
  • 명시적 증상 (빌드 실패·500 에러·테스트 실패) 전담
  • 위임 호출 가능: 라운드 소모 없이 빠르게 해결
위치: QC 디버깅 1종 · 평가가 "박살내라" 위임 시 호출

⚡ 위임 규칙 — 누가 누구를 부르는가

호출자증상위임 대상
