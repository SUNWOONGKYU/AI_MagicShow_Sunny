# 21. AI는 틀릴 수 있음을 인정받는 지구상에서 거의 유일한 존재임을 인정하기

## 한 줄 정의

AI 오류 가능성을 **다단계 검증으로 막되**, 그 검증 과정에서 오히려 새로운 통찰이 솟아나는 **창발 현상을 의식적으로 포착**하는 본인 운용 철학.

## 왜 이 노하우가 중요한가

세상에 "틀려도 된다"가 사회적으로 허용되는 존재는 거의 없다. 의사·변호사·교사가 틀리면 사고가 난다. 그런데 **AI는 틀릴 수 있다는 것이 공식 속성**이다. 이 비대칭이 AI 운용의 양날의 검이다.

**나쁜 운용**: AI가 틀릴 수 있으니 못 쓴다 → 1단계 도구로 회귀.
**나쁜 운용**: AI가 자신만만하게 답하니 그대로 믿는다 → SKILL_ATLAS 사고.
**좋은 운용**: 틀릴 가능성을 시스템으로 감안하면서, 그 검증 과정에서 사람 단독으론 못 떠올렸을 통찰을 잡아낸다.

본인은 후자를 4,000시간 굴리며 체감했다. AI에게 검증을 시키면 **"제가 보기엔 이 부분이 약점입니다"** 하고 나오는 답이 종종 사람의 사각지대였다. 그게 창발이다.

## 핵심 개념

**다단계 검증 4 레이어**

| 레이어 | 역할 | 도구 |
|--------|------|------|
| L1 자기 비판 | AI가 자기 결과물 약점 찾기 | #6 4종 품질관리 스킬 |
| L2 페르소나 토론 | 3 전문가 + Devil's Advocate | #13 pro-persona-debate-코어6 |
| L3 별도 에이전트 | Verification Agent ≠ Task Agent | review-evaluate-코어1 |
| L4 사람 클릭 테스트 | 브라우저 실제 동작 확인 | Playwright + 사람 눈 |

**SKILL_ATLAS 사고 교훈** (본인 글로벌 CLAUDE.md에 박아둠):
> *"curl 200 ≠ 동작함"*
> "Task Agent가 자신의 UI를 Verified 처리하면 안 된다. 반드시 별도 Verification Agent가 클릭 테스트를 수행해야 한다."

**창발 포착 3 신호**:
1. AI가 *"흥미로운 점은..."*, *"한편..."*, *"의외로..."* 같은 표현을 쓸 때
2. 검증 단계에서 원래 명세에 없던 측면을 지적할 때
3. 다른 페르소나끼리 충돌하는 지점

이 셋이 나오면 즉시 메모. 그게 본인 다음 특허·다음 스킬의 씨앗이 된다.

## 실전 사용법

**1단계 — 모든 결과물에 L1 자기 비판 강제**
프롬프트 끝에 "이 결과물의 약점·빠진 것·반박점을 3개 이상 찾아라."

**2단계 — 중요 결과물엔 L2 페르소나 토론**
*"3 전문가 + Devil's Advocate로 토론하고 합의안 내라."* `pro-persona-debate-코어6` 스킬 사용.

**3단계 — 시각 결과물엔 L3 별도 에이전트 + L4 클릭 테스트**
- Task Agent가 UI 만들기
- Verification Agent(다른 인스턴스)가 Playwright 스크린샷 + 클릭
- 본인이 브라우저로 직접 확인

**4단계 — 창발 신호 즉시 캡처**
검증 중 *"흥미로운 점"*이 나오면 `G:\내 드라이브\Claude-Wiki\` 임시 메모. 본인은 SAL Grid 특허 핵심 아이디어 한 조각이 이 단계에서 나왔다.

**5단계 — 창발 → 자산화 루프**
캡처된 창발 → #15 SVG 정리 → 스킬 자산화 → #4 Wiki 누적. 다음 작업의 입력이 됨.

**본인 검증 표준 체크리스트**:
- [ ] L1 자기 비판 통과 (약점 3개 이상)
- [ ] L2 페르소나 토론 (Devil's Advocate 포함)
- [ ] L3 별도 에이전트 검증 (자기 검증 금지)
- [ ] L4 사람 클릭 테스트 (시각물의 경우)
- [ ] 창발 신호 캡처 여부

**KPI**: 중요 결과물의 4 레이어 통과율 100%, 자기 검증으로 끝낸 산출물 0건, 월간 창발 신호 캡처 ≥ 5건.
