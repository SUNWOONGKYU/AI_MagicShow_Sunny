# 18. 대량 검색 시 토큰비를 줄이려면 네이버·구글 검색 활용하기

## 한 줄 정의

AI 내장 웹 검색은 토큰을 무겁게 태우므로 **대량 정보 수집은 네이버·구글 직접 검색으로 처리**하고, AI에는 정제된 결과만 투입해 토큰비를 절감하는 운용 원칙.

## 왜 이 노하우가 중요한가

본인 4,000시간 운용에서 가장 큰 비용 누수가 발생하는 지점이 **AI에게 "찾아봐"를 시키는 순간**이다. Claude Code 내장 WebSearch는 한 쿼리당 검색 결과 페이지 본문을 토큰화해 컨텍스트로 끌어들인다. 한 번 검색에 1만~3만 토큰이 우습게 들어간다.

특허 출원서 한 건을 위해 선행기술 50건을 검색하면 그 자체로 50만~150만 토큰. 30개 동시 운용 환경에서 인스턴스 셋만 검색을 돌려도 5시간 Rate Limit이 한 시간 만에 소진된다.

반면 네이버·구글 검색창에 사람이 직접 키워드 넣고 결과 제목·요약만 추려서 AI에 던지면 같은 정보를 **1/20 토큰**으로 처리할 수 있다. 컨텍스트도 깨끗하게 유지된다.

## 핵심 개념

**검색 비용 = 쿼리 횟수 × 결과 페이지 토큰 × 인스턴스 수**

토큰 절감 3원칙:

| 단계 | AI 수행 | 사람 수행 |
|------|---------|-----------|
| 키워드 도출 | O (AI 강점) | - |
| 검색 실행 | X (비쌈) | **O (네이버·구글)** |
| 결과 1차 필터 | X | **O (제목·요약 보고)** |
| 본문 정독·종합 | **O (AI 강점)** | - |

핵심은 **AI는 사고 엔진, 검색은 사람의 눈**으로 역할 분리. 사람이 5초 만에 거를 수 있는 무관한 결과를 AI에게 토큰으로 태워 거르게 하는 것은 낭비다.

대안 도구:
- **네이버**: 한국어 자료, 블로그·카페·뉴스
- **구글**: 영문 논문·GitHub·StackOverflow·해외 특허
- **구글 학술검색**: 논문 PDF 직링크
- **KIPRIS·Google Patents**: 특허 검색은 반드시 전용 사이트
- **DuckDuckGo**: 익명 검색·중복 제거

## 실전 사용법

**1단계 — AI에 키워드 5~10개 추출 시키기**
"SAL Grid 개발방법론 관련 선행기술 검색용 키워드 10개 뽑아줘. 영문·한글 혼합."

**2단계 — 사람이 네이버·구글에 직접 검색**
키워드별 상위 10건 제목·URL 메모장에 복사. 본인은 `G:\내 드라이브\` 임시 .txt에 모은다.

**3단계 — AI에 1차 필터 시키기**
"이 50건 중 SAL Grid 3차원 좌표 관점에서 관련성 높은 것 10건 골라."

**4단계 — 사람이 10건 본문 PDF·HTML 다운로드**
AI 내장 검색이 아니라 직접 다운로드. 토큰 0.

**5단계 — AI에 본문 투입해 비교·종합**
이때부터 AI 강점 발휘. 차별점·약점·창발 포인트 추출.

**본인 운용 결과**: 특허 10-2026-0009425 SAL Grid 출원 시 선행기술 80건 검토를 본 방식으로 처리. AI 내장 검색 추정치 대비 **토큰비 약 1/15**로 완료. 같은 작업을 #19 트랙터 운전 패러다임과 결합하면 한 번 익혀둔 검색 루틴이 매 작업마다 비용을 깎는다.

**주의**: 시급한 단답·실시간 정보(주가·환율 등)는 AI 내장 검색이 더 빠르다. **대량·심층** 검색에만 본 방식 적용.
