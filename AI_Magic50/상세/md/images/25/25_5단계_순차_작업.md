# 25. 5단계로 나누어 순차적으로 작업시키기

## 한 줄 정의

큰 작업을 한 번에 던지지 말고 **5개 단계로 쪼개서 순차 진행**하며 각 단계 결과물을 확인 후 다음으로 넘어가는 본인 표준 워크플로우. 슬라이드쇼 20번 *"매직 2"*에서 강의 메인 메시지로 인용.

## 왜 이 노하우가 중요한가

본인 4,000시간에서 가장 많이 본 실패 패턴: **"이거 한 번에 다 해줘"**. AI가 6,000자짜리 결과물을 한 번에 토해내면 검증 비용이 폭증한다. 약점을 찾는 데 결과물 작성보다 더 많은 시간이 든다.

같은 작업을 5단계로 쪼개면:
- 각 단계 결과물 1,200자
- 즉시 확인·수정 가능
- 잘못 가도 한 단계 분량만 폐기
- 사용자의 통제력 + AI의 정확도 둘 다 확보

이는 #3 아젠다별 승인 패턴의 워크플로우 버전이고, #10 MBO의 단위 작업 원칙이며, #34 Plan Mode의 실행 단계 구조다. 본인 슬라이드 20번에서 *"매직 2 = 5단계 순차"*로 강조한 이유.

## 핵심 개념

**범용 5단계 템플릿**

| 단계 | 명칭 | AI 작업 | 사용자 확인 |
|------|------|---------|-------------|
| S1 | 분석·이해 | 자료 읽기·요구사항 정리 | 이해도 점검 |
| S2 | 설계·계획 | 구조·아키텍처 제안 | 방향 승인 |
| S3 | 구현·생산 | 실제 결과물 만들기 | 1차 결과물 검토 |
| S4 | 검증·수정 | 자기 비판 + 약점 보강 | 품질 확인 |
| S5 | 정리·자산화 | 회고·문서·Wiki 정리 | 다음 작업 자산 확정 |

**작업 유형별 변형**:

- **개발 작업**: 분석 → 아키텍처 → 코딩 → 테스트 → 배포
- **문서 작업**: 자료 수집 → 목차 → 초안 → 교정 → 최종
- **이미지 작업**(#47): 컨셉 → 5모델 생성 → 베스트 5선 → Pillow 후처리 → 게재
- **특허 작업**(#7): 선행기술 검색 → 차별점 → 청구항 → 명세서 → 출원

핵심은 **각 단계 끝 = 사용자 확인 게이트**. 게이트 없이 다음 단계 진입 금지.

## 실전 사용법

**1단계 — 작업 시작 시 5단계 미리 명시**
*"이 작업을 다음 5단계로 진행. S1: 종합정리 MD 5개 항목 원문 확인. S2: 5섹션 구조 초안. S3: 본문 작성. S4: 자기 비판·약점 보강. S5: 보고."*

**2단계 — Plan Mode와 결합** (큰 작업)
#34 Plan Mode로 5단계 계획 먼저, 사용자 승인, 실행 모드 전환. SAL Grid 프로젝트는 자동으로 이 패턴.

**3단계 — 매 단계 끝 보고 형식 통일**
```
S{N} 완료
- 산출물: <파일 경로>
- 핵심 결과: <한 줄>
- 다음 단계 진입 여부: 사용자 결정
```

**4단계 — 단계 간 컨텍스트 인계**
직전 단계 결과를 다음 단계 입력으로. 본인은 임시 .md 파일에 단계별 누적해 #30 컨텍스트 관리.

**5단계 — 최종 단계는 반드시 자산화**
S5에서 #4 Wiki·#39 Slash Command·#23 CLAUDE.md 중 하나로 자산화. 이게 빠지면 다음 작업이 처음부터.

**본인 운용 사례**: 본 AI Magic 48 시리즈 작성도 5단계 — (1) 종합정리 작성 → (2) 슬라이드 50장 → (3) 상세 MD 본문 (현재 단계) → (4) 검증·교정 → (5) ax-on.net 게재. 각 단계 끝마다 게이트.

**자주 빠지는 함정**:
- 5단계 미리 안 짜고 즉흥 진행 → 중간에 길 잃음
- 게이트 안 거치고 폭주 → S3에서 망쳤는데 S5까지 감
- 단계 인계 누락 → S2 계획과 다른 S3 결과물
