# 8. 엔비디아 NeMoTron 100만 한국인 합성 데이터셋 활용하기

## 한 줄 정의

NVIDIA가 2026년 공개한 **합성 한국인 페르소나 100만 명** 데이터셋(Nemotron-Personas-Korea)을 본인 챗봇·SLM·평가 셋의 한국어 학습·검증·평가 자료로 활용하는 노하우. 한국어 LLM 운용에서 *"한국 정서·지명·직업 분포가 반영된 자연스러운 발화"* 를 무료로 확보할 수 있는 거의 유일한 대규모 자원이다.

## 왜 이 노하우가 중요한가

한국어로 챗봇을 학습·평가시킬 때 가장 먼저 부딪히는 벽은 **데이터 부족**이다. 영어권은 Common Crawl·OpenAssistant·Anthropic HH-RLHF 같은 대규모 공개 자원이 풍부하지만, 한국어는 그 1/10 수준도 안 된다. 본인이 4,000시간 운용하면서 챗봇 30개를 굴리는 동안 깨달은 것 한 가지 — *"영어 데이터로 학습한 모델에 한국어를 시키면 발화는 가능하지만 직업·지명·문화 맥락이 어긋난다"*. 예를 들어 *"고양시 일산서구 거주, 식약처 GMP 감사관, 40대 후반"* 같은 페르소나가 나와야 할 자리에 *"서울 강남, 회사원, 30대"* 같은 일반적 페르소나만 반복 등장한다.

이 문제를 해결하는 방법은 셋 중 하나다. ① 직접 데이터 수집(저작권·개인정보·시간 비용 폭발), ② 외주 라벨링(1만 건당 수백만원), ③ **합성 데이터 활용**. 본인은 ③을 택했고, 그 핵심 자원이 NeMoTron Personas Korea다. NVIDIA가 자사 Nemotron 모델로 생성한 100만 합성 한국인 페르소나가 HuggingFace에 무료 공개되어 있다 — *직업·거주지·취미·언어 스타일·생애 사건*이 시·군·구 단위까지 분포된 자연 한국어 텍스트.

여기서 가장 중요한 사실은 **합성 데이터지만 통계적 분포가 한국 인구통계와 정합적**이라는 점이다. 실제 인구 비례에 맞춰 직업군·연령대·지역이 분포되어 있어, 1,000명을 무작위 샘플링하면 한국 사회 단면을 그대로 들여다볼 수 있다. 본인 챗봇 학습·검증에서는 이 통계적 정합성이 결정적이다 — *"이 챗봇이 다양한 한국인의 다양한 질문에 자연스럽게 응답하는가"* 를 객관적으로 측정할 수 있는 평가 셋의 토대가 되기 때문.

또 하나의 결정적 가치는 **개인정보 리스크가 0**이라는 점이다. 합성 데이터이므로 GDPR·개인정보보호법 어디에도 걸리지 않는다. 본인 챗봇 fine-tuning, 평가 자동화, 기획서 페르소나 시뮬레이션 등 어떤 용도로도 자유롭게 쓸 수 있다.

## 핵심 개념

### 데이터셋 구조

NeMoTron Personas Korea는 1행 1페르소나 형식의 JSONL/Parquet로 배포된다. 각 행에는 다음 필드가 들어 있다.

| 필드군 | 항목 |
|--------|------|
| 인구통계 | 이름·나이·성별·거주지(시/군/구)·직업·교육 |
| 라이프스타일 | 가족 구성·취미·자주 이용하는 매체 |
| 언어 스타일 | 사투리 유무·평어/존댓말 선호·자주 쓰는 표현 |
| 생애 사건 | 최근 관심사·고민·구매 이력 패턴 |

100만 건 = 한국 인구의 약 50명 중 1명꼴. 시·군·구 단위 분포까지 되어 있어 *"부산 해운대구 60대 자영업자"* 같은 좁은 페르소나도 수백~수천 건 추출 가능하다.

### 활용 3축

본인은 이 데이터셋을 세 축으로 나눠 쓴다. 각 축의 목적과 사용량이 다르다.

| 축 | 목적 | 표본 수 | 결과물 |
|---|---|---|---|
| **학습** | 챗봇 SFT/DPO 한국어 보강 | 1만~10만 | fine-tuned 모델 |
| **검증** | 챗봇 응답 품질 회귀 테스트 | 100~1,000 | 자동 평가 점수 |
| **평가** | 신규 페르소나에 대한 generalization | 100~500 | 사용자 여정 KPI |

### 학습용 활용 (SFT 보강)

본인 도우미형 챗봇에 한국어 SFT(Supervised Fine-Tuning) 데이터셋을 만들 때, NeMoTron 페르소나 1만 명에서 *"이 사람이 챗봇에 묻고 싶을 만한 질문 3개씩"* 을 합성한다. 즉 페르소나 메타정보(직업·관심사·생애사건)를 입력으로 주고, GPT-4 / Claude로 자연스러운 질문·답변 쌍을 생성한다. 결과물은 1만 페르소나 × 3쌍 = 3만 SFT 페어. 이를 SFT 학습 자료에 추가하면 *"질문 다양성과 직업적 맥락 정합도"* 가 눈에 띄게 올라간다 — 본인 평가에서 직업 맥락 적합도가 73%→91%까지 향상된 사례가 있다.

### 검증용 활용 (회귀 테스트 셋)

가장 자주 쓰는 축. 본인 챗봇을 수정할 때마다 *"수정이 한국어 응답 품질을 떨어뜨리지 않았는가"* 를 자동으로 검증해야 한다. NeMoTron에서 1,000 페르소나를 고정 표본으로 추출해 *"이 페르소나가 던질 만한 질문 1개"* 만 합성하면 1,000개 회귀 테스트 셋이 만들어진다. CI 파이프라인에서 매 PR마다 이 1,000개를 챗봇에 던져 응답을 받고, 별도 LLM 채점기(review-evaluate-코어1)로 5기준 평가 → 평균 점수가 직전 빌드보다 떨어지면 PR 차단. 이게 챗봇 개발의 *"E2E 12/12 통과"* 에 해당하는 데이터 레이어 KPI다.

### 평가용 활용 (Generalization 측정)

학습에 안 쓴 100~500 페르소나를 별도로 떼어 hold-out 셋으로 둔다. 신규 모델이 학습한 적 없는 페르소나에 대해서도 자연스럽게 응답하는지 확인하는 마지막 관문. *"학습 페르소나에서만 잘하고 신규에서는 무너지는"* overfitting을 잡는 도구다.

### 한국어 LLM·SLM 운용에서의 위치

한국어 모델 운용에서 NeMoTron의 위치는 분명하다 — **AI Hub 공공 데이터셋과의 보완재**. AI Hub는 라벨링이 정밀하지만 도메인이 좁고 양이 제한적이다. NeMoTron은 라벨이 거칠지만 페르소나 다양성과 양이 압도적이다. 둘을 섞어 쓰면 *"정밀한 도메인 데이터(AI Hub) + 다양성 보강(NeMoTron)"* 의 균형이 잡힌다.

SLM(Small Language Model) 학습에서도 가치가 크다. 1B~7B 규모 한국어 SLM을 직접 굳이 만들 때 NeMoTron 페르소나로 합성한 SFT 데이터가 학습 코퍼스의 30~40%를 채울 수 있다. *"공공 데이터만으로는 도메인 편향이 심한"* 한국어 SLM의 약점을 보완하는 결정타.

## 실전 사용법

### 1단계 — 데이터셋 다운로드

HuggingFace에서 `nvidia/Nemotron-Personas-Korea` 검색 → `datasets.load_dataset()` 한 줄로 로드. 100만 건 전체는 수십 GB이므로 streaming 모드 권장. 본인은 G드라이브에 한 번 다운받고 C드라이브 작업폴더로 필요 분량만 복사해 쓴다(#36과 짝).

### 2단계 — 필터링 + 샘플링

목적별로 페르소나를 골라낸다. 예 — 본인 도우미형 챗봇이 *"40대 자영업자 + 공공 행정 관심"* 타깃이면 그 조건으로 필터링 → 5,000명 추출. 단순 무작위 샘플링은 분포 편향을 그대로 받으므로, 직업·지역·연령 stratified sampling으로 균형을 잡는다.

```python
# 의사코드
ds = load_dataset("nvidia/Nemotron-Personas-Korea", split="train")
filtered = ds.filter(lambda r: r["age"] in range(40, 50) and "자영업" in r["occupation"])
balanced = stratified_sample(filtered, by=["region", "education"], n=5000)
```

### 3단계 — 질문·응답 합성

페르소나 메타정보를 컨텍스트로 LLM에 주입해 *"이 사람이 챗봇에 던질 질문 N개"* 를 합성. 합성 품질은 LLM 모델별로 차이가 크다. 본인은 Claude Sonnet 4를 쓴다 — 한국어 자연스러움과 직업 맥락 반영도 둘 다 가장 높다. GPT-4o는 한국어 직업 어휘에서 가끔 어색한 단어를 만든다(예: "변리사"를 "특허 대리인"으로 의역).

### 4단계 — 회귀 테스트 셋 고정

검증용 1,000 페르소나는 한 번 추출하면 **고정**한다. 매번 무작위 추출하면 점수가 노이즈에 흔들려 회귀 신호를 못 잡는다. 페르소나 ID를 JSON으로 저장 후 CI에서 같은 ID만 반복 사용. 이게 *"베이스라인 점수"* 의 의미를 만든다.

### 5단계 — 평가 자동화 결합

회귀 셋 1,000건을 챗봇에 던지고 응답을 받은 뒤, review-evaluate-코어1(#6)의 5기준 채점을 자동 적용. 결과는 단일 점수(0~100)로 압축. 직전 빌드 대비 -2점 이상 하락 시 PR 차단. 이 흐름이 본인 챗봇의 *"한국어 품질 회귀 0건 보장"* KPI를 데이터 레이어에서 굳혀준다.

### 6단계 — 사용자 여정 KPI와의 결합

데이터 레이어 점수만으로는 부족하다(SKILL_ATLAS 사고 교훈). 회귀 셋 통과 + Playwright 클릭 테스트로 *"실제 챗봇 UI에서 페르소나 5명의 질문이 정상 표시·응답되는가"* 까지 확인해야 진짜 통과. 본인은 회귀 1,000개 데이터 레이어 + 클릭 테스트 5명 사용자 여정을 한 빌드의 KPI 묶음으로 본다.

## 본인 운용 패턴

본인 ax-on.net 도우미형 챗봇은 NeMoTron 5만 페르소나로 SFT 보강한 버전과 미보강 버전을 A/B 비교한 결과, 한국어 직업 맥락 적합도 18%p 차이가 났다. 이 격차가 *"공공 행정 도우미"* 라는 챗봇 정체성에서 결정적 — 보강하면 *"식약처 GMP 감사관이 신규 의약품 인허가 절차를 묻는다"* 같은 좁은 질문에도 정합 응답이 나오고, 미보강하면 *"인허가 절차"* 라는 일반론으로 미끄러진다.

또 하나, NeMoTron은 *합성*이라는 점을 잊지 않는다. 100% 신뢰하지 않고 별도 사실 검증(현무 BuzzLab 시뮬레이션 또는 pro-persona-debate)으로 *"이 합성 페르소나의 답변이 실제 그 직군 사람의 응답과 합치하는가"* 를 표본 검증한다. 100건 정도 표본 검증으로 합성 데이터의 신뢰 구간을 찍는다.
