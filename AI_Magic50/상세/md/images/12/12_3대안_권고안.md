# 12. 3개 이상 대안 + 장단점 + 최종 권고안

## 한 줄 정의

AI에게 단답을 받지 않고 **"3개 이상 대안 + 각 장단점 + 최종 권고"** 패턴을 강제해, 단일 답에 갇히는 인지 편향을 매 의사결정마다 차단하는 본인 표준 프롬프트.

## 왜 이 노하우가 중요한가

*"하나만 알려줘"* 는 AI 운용에서 가장 위험한 한 마디다. AI는 학습된 분포의 중심값을 대답하고, 사용자는 *"AI가 그렇다니까 그런 줄 알았다"* 로 정착시킨다. 4,000시간 동안 사업 결정·기술 선택·문서 톤 모두에서 같은 사고가 반복됐고, 결국 **모든 결정 프롬프트의 끝에 이 패턴을 못 박아두는 것**이 표준이 됐다. 핵심은 *"3개 이상"* 이라는 강제. AI가 2개 내고 끝내려 하면 1개가 약 대비용으로 만들어진 허수다. 3개를 시키면 비로소 *"진짜 다른 축"* 이 드러난다. 권고안까지 시켜야 AI가 자기 추천에 책임지는 톤으로 답하고, 사용자는 *"권고안의 약점"* 을 다시 묻는 식으로 깊이 들어갈 수 있다.

## 핵심 개념

```
[질문] → [대안 A] [대안 B] [대안 C] → [장단점 표] → [최종 권고]
              ↓
       사용자 재질문: "권고안의 가장 큰 약점은?"
              ↓
       AI: 약점 + 회피 방안
              ↓
       결정 또는 다음 라운드
```

| 구성 | 역할 |
|------|------|
| 대안 ≥ 3 | 인지 다양성 확보 |
| 장·단점 표 | 비교 가능성 |
| 최종 권고 | AI의 책임진 1선택 |
| 약점 재질문 | 권고안 강화 |

본인 사고: *"단일 답 = 사고 정지"*. **#13 전문가 페르소나 토론**의 가벼운 일상 버전. **#21 AI 오류 인정**의 운용 도구.

## 실전 사용법

**표준 프롬프트(고정)**:
```
[질문 본문]

답변 형식:
1) 서로 다른 축의 대안을 최소 3개 제시
2) 각 대안의 장점 3개·단점 3개를 표로
3) 최종 권고안 1개 + 권고 이유 3줄
4) 권고안의 가장 큰 약점도 명시
```

**본인 운용**: `.claude/commands/3대안.md`(**#39 Slash Commands**)로 등록해 `/3대안 <질문>` 한 줄로 호출. 30개 인스턴스 어디서든 동일 톤. **#34 Plan Mode** 안에서 호출하면 실행 전 의사결정 게이트가 자동 박힌다.

**예시 — 강의 슬라이드 톤 결정**:
- A: 미니멀 텍스트형 / B: 인포그래픽 SVG형 / C: 코드+다이어그램 혼합
- 표 비교 → 권고: B (4,000시간 시각자산 누적과 정합) → 약점: 제작 시간 +30%
- 약점 회피: **#15 SVG 스킬 자산화**로 제작 시간 흡수

**KPI**: 의사결정 당 대안 수 ≥ 3, 권고안 약점 명시율 100%, *"AI가 그렇다니까"* 식 후회 0건.

**금지** — 토론에서 *"빨리 정해, 그냥 하나만"* 으로 회귀하는 것. 시간 없으면 대안 3개를 1줄씩으로 줄이되 개수는 유지.
