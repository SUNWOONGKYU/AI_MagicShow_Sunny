# 39. Slash Commands 활용하기

## 한 줄 정의

**`.claude/commands/` 폴더에 마크다운 파일 하나만 만들면 그 파일명이 그대로 `/명령어` 로 동작**하는 본인 전용 단축 명령어 시스템. 자주 쓰는 프롬프트 한 덩어리(특허 초안·3대안 비교·품질 4종 검토)를 *"타이핑 한 번"* 으로 압축하는 가벼운 자산화 도구. 본격 스킬(SKILL.md)로 격상시키기 전 단계의 1차 캡슐.

## 왜 이 노하우가 중요한가

본인 4,000시간 누적에서 가장 자주 반복되는 진실 — *"같은 프롬프트를 100번 친다는 건, 그 프롬프트가 자산화 돼야 한다는 신호"*. *"이번에는 특허 초안 작성해줘. 차별점은 이렇고, 청구항은 저렇고, 출원 형식은..."* 이 50줄짜리 프롬프트를 매번 손으로 치면 사람이 망가진다. 그걸 `commands/특허초안.md` 한 파일로 박아두면 `/특허초안` 한 줄로 끝.

슬래시 커맨드는 **사용자 명령을 압축**하는 도구다. 훅(#38)이 *"AI 행동을 자동화"* 한다면, 슬래시 커맨드는 *"사용자 행동을 압축"* 한다. 둘은 정확히 반대 방향에서 같은 목표(반복 제거)를 친다.

본인 사고가 여기서 단계적으로 발전한다 — *"같은 프롬프트 3회 → 슬래시 커맨드, 같은 슬래시 커맨드 10회 → 스킬(SKILL.md) 격상, 같은 스킬 다른 PC에서도 → 글로벌 스킬"*. 본인 글로벌 스킬 41개는 전부 이 진화 경로를 거쳤다. 슬래시 커맨드는 자산화의 1차 캡슐이다.

또 하나 — 슬래시 커맨드는 **프로젝트 단위 자산화**를 가능하게 한다. `.claude/commands/` 가 프로젝트 폴더 안에 있으면 그 프로젝트에서만 발동, 글로벌은 `~/.claude/commands/` 에 두면 전 PC·전 프로젝트에서 발동. 4,000시간 누적의 *"한 번 만들면 영원히 쓰는 자산"* 의 가장 가벼운 형태.

## 핵심 개념

### 두 위치 — 글로벌 vs 프로젝트

| 위치 | 적용 범위 | 본인 사용 |
|------|-----------|----------|
| `~/.claude/commands/` | 모든 프로젝트 | `/mbo`, `/특허초안`, `/3대안`, `/품질4종` |
| `.claude/commands/` (프로젝트 루트) | 그 프로젝트 한정 | `/배포`, `/검수`, 프로젝트별 단축어 |

본인은 **공용 자산은 글로벌, 프로젝트 특화는 프로젝트 폴더**. 새 PC 셋업 시 `~/.claude/commands/` 만 통째로 복사하면 단축 명령어가 다 따라온다.

### 파일 형식 — MD 한 장

```markdown
---
description: "특허출원서 초안 작성 (차별점 도출 + 청구항 + 명세서)"
argument-hint: "[발명 키워드]"
---

# /특허초안

당신은 특허 명세사다. 다음 절차를 수행하라.

1. $ARGUMENTS 키워드로 KIPRIS·Google Patents 유사 특허 5건 조사
2. 차별점 표(우리 vs 5건) 작성
3. 독립청구항 1개 + 종속청구항 5개 + 명세서 골격
4. KPI: 변리사 검토 시 보완 요청 ≤ 3건

본인 특허 10-2026-0009425 SAL Grid 출원 양식을 참조하라.
```

`$ARGUMENTS` 가 인자 자리. `/특허초안 AI 챗봇` → `$ARGUMENTS` = "AI 챗봇" 으로 치환 후 프롬프트 발동. **MD 파일 하나가 곧 하나의 슬래시 커맨드**.

### YAML 프론트매터 옵션

| 키 | 용도 |
|----|------|
| `description` | `/help` 에서 보여줄 설명 |
| `argument-hint` | 인자 자리 표시(`/특허초안 [발명 키워드]`) |
| `model` | 이 명령에만 다른 모델 강제 (`opus`/`sonnet`/`haiku`) |
| `allowed-tools` | 도구 화이트리스트 (보안 강화) |

`model` 키가 강력하다 — `/3대안` 같은 깊은 추론 명령은 항상 `opus` 강제, `/포맷` 같은 단순 변환은 `haiku` 강제. #44(`/model` 명령) 의 자동화 버전.

### 본인 슬래시 커맨드 4종 (대표 사례)

**1. `/mbo`** — 가장 많이 쓰는 명령. 대화 맥락에서 자동 도출해 4표 양식 MBO 목표서 생성. 사용자 *"MBO"* 한 단어가 수백 줄짜리 합의 명세서로 변환된다. (#10 짝)

**2. `/특허초안`** — 본인 특허 10-2026-0009425 SAL Grid 출원 경험을 양식화. KIPRIS 조사 → 차별점 표 → 청구항 → 명세서 골격까지 한 번에. 변리사 미팅 전 1시간 작업.

**3. `/3대안`** — 어떤 결정이든 3가지 대안 + 권고안 1개로 정리. *"이거 어떻게 할까"* 질문에 자동으로 비교표·트레이드오프 분석. (#12 짝)

**4. `/품질4종`** — 4종 품질관리 스킬 동시 실행. review-evaluate-코어1 + pro-persona-debate-코어6 + 5times-debug-loop-코어3 + 주작-sal-da 4개를 순차 호출. (#6 짝)

### 슬래시 커맨드 → 스킬 격상 흐름

본인 자산화 4단계:

```
1. 인라인 프롬프트 (매번 손으로)
   ↓ (3회 반복 시)
2. 슬래시 커맨드 (commands/X.md)
   ↓ (10회 반복 + 다중 단계 필요)
3. 스킬 (skills/X/SKILL.md)
   ↓ (전 PC·전 프로젝트 사용)
4. 글로벌 스킬 (~/.claude/skills/)
```

본인 글로벌 스킬 41개 전부 이 경로를 거쳤다. 처음에 mbo-코어5도 `/mbo` 슬래시 커맨드였고, 청룡-sal-grid-dev도 `/sal` 명령으로 시작했다. **승급 기준은 단순하다 — "단일 프롬프트로 안 되고 여러 단계가 필요해진 순간"** = 스킬로 격상.

## 실전 사용법

### 1단계 — 프롬프트 3회 반복 감지

같은 프롬프트를 손으로 3번 친 자신을 발견하면 멈추고 commands/ 폴더 연다. 그 3번이 5번 되기 전에 잡아야 한다.

### 2단계 — MD 파일 작성

```bash
# 글로벌 (모든 프로젝트)
~/.claude/commands/내명령.md

# 프로젝트 한정
프로젝트루트/.claude/commands/내명령.md
```

YAML 프론트매터 + 프롬프트 본문. `$ARGUMENTS` 가 필요하면 자리만 잡아둔다.

### 3단계 — 즉시 사용

```
/내명령 인자값
```

설치·재시작·캐시 삭제 같은 거 없음. 파일 저장 즉시 발동.

### 4단계 — 격상 판단

| 신호 | 행동 |
|------|------|
| 명령 안에서 여러 도구 호출 필요 | 스킬로 격상 |
| 명령 안에서 다른 슬래시 호출 필요 | 스킬로 격상 |
| 5개 이상 인자 필요 | 스킬로 격상 |
| 단일 프롬프트로 충분 | 슬래시 커맨드 유지 |

### KPI (양 레이어)

- **데이터 레이어** — `commands/` 폴더에 N개 파일 존재
- **사용자 여정** — 각 명령을 실제 호출했을 때 인자 치환·결과 산출 모두 정상 (월 1회 자기 점검)

*"파일이 만들어졌다"* 는 데이터 레이어 KPI 일 뿐. 본인이 실제로 호출해서 결과가 의도대로 나오는지 사용자 여정 검증 — 슬래시 커맨드도 자기 검증 금지(별도 슬롯에서 호출 테스트).

### 자주 만나는 함정

| 증상 | 원인 | 해결 |
|------|------|------|
| `/명령` 안 보임 | 위치 잘못 | `~/.claude/commands/` 또는 프로젝트 `.claude/commands/` |
| `$ARGUMENTS` 그대로 출력됨 | 변수명 오타 | `$ARGUMENTS` (대문자, 그대로) |
| 인자 공백 잘림 | 따옴표 미사용 | `/명령 "공백 포함 인자"` |
| description 안 보임 | YAML 들여쓰기 오류 | `---` 위아래 빈 줄 확인 |

## 본인 운용 패턴

본인 슬래시 커맨드 폴더는 30개 정도. 그중 절반은 글로벌(어디서나), 절반은 프로젝트별. 글로벌 30개의 누적 사용 횟수가 만 단위. *"안 만들었으면 평생 손으로 쳤을 시간"* — 4,000시간 누적의 진짜 무기 중 하나.

격상은 보수적으로 — 슬래시 커맨드로 충분한데 굳이 스킬로 올리지 않는다. 스킬은 SKILL.md + 보조 파일 + 트리거 등록까지 들어가서 유지보수 비용이 다르다. *"단일 프롬프트 한 장으로 충분한가"* 가 격상 여부의 진짜 기준.

훅(#38) 과 짝 — 훅이 *AI 자동 행동*, 슬래시 커맨드가 *사용자 명령 압축*. 둘 다 settings.json/commands 폴더 기반 자산화라서 PC 이전 시 함께 따라온다.
