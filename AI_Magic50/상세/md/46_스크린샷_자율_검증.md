# 46. 스스로 스크린샷 찍어서 문제점 찾아 스스로 수정하기

## 한 줄 정의

Claude Code가 결과물 화면을 자기가 캡처하고 자기가 검증하고 자기가 고치는 **Playwright 기반 자율 루프** — `"curl 200 ≠ 동작함"`을 코드 단에서 직접 구현한 검증 인프라.

## 왜 이 노하우가 중요한가 — SKILL_ATLAS 사고

본인 글로벌 CLAUDE.md에 박혀 있는 UI 검증 철칙은 SKILL_ATLAS S5 배포 사고에서 나왔다. **curl로 200 확인하고 Verified 처리**했지만 사용자가 실제 브라우저에서 보니:

- "시작하기"·"더 알아보기" 버튼 — `href` 없어서 클릭 무반응
- 4개 은하 원 — `<div>`로 만들어 클릭 불가
- "View All" — 존재하지 않는 `/rankings`로 404
- 랭킹 카드 — `/skills/${uuid}` 경로·파라미터 전부 틀림

데이터 레이어 KPI("테이블에 데이터가 있다")는 통과했지만 **사용자 여정 KPI**(주요 버튼 4개 클릭 시 올바른 라우트로 네비게이트)는 0점이었다. #46은 이 사용자 여정 KPI를 **자동으로** 돌리는 루프다.

## 핵심 개념 — 본인 글로벌 CLAUDE.md UI 검증 철칙 (인용)

> **"curl 200 ≠ 동작함"** — HTTP 상태코드만 보고 "작동한다"고 판단하지 마라.
>
> 1. UI Task 검증 시 `curl 200` → Verified 금지. 실제 브라우저(또는 Playwright)에서 클릭 테스트 필수.
> 2. 배포 후 첫 액션은 `curl`이 아니라 "배포 URL을 브라우저로 직접 열어 주요 버튼/링크를 모두 클릭해본다" 이다.
> 3. KPI에 사용자 여정 지표를 반드시 포함한다.
> 4. `href` 없는 `<Button>`, 클릭 가능해 보이는 `<div>`는 버그로 간주.
> 5. **자기 검증 금지** — Task Agent가 자신의 UI를 Verified 처리하면 안 된다. 반드시 별도 Verification Agent가 클릭 테스트.

자율 루프 단계:
```
Task Agent: 코드 작성·배포
   ↓
Verification Agent (별도 인스턴스):
   1. Playwright로 URL 접속
   2. 주요 버튼·링크 모두 클릭
   3. 스크린샷 + 라우트 결과 캡처
   4. dead-link/잘못된 경로 검출
   ↓
재 Task Agent: 검출된 결함 수정 (최대 5회 — 5times-debug-loop)
```

## 실전 사용법

**1단계** — `5times-debug-loop-코어3` 스킬 발동. 이 스킬이 Playwright로 화면 캡처하고 시각적 차이를 직접 본다.

**2단계** — 검증용 Playwright 스크립트 자동 생성. `page.goto(URL)` → `page.click(<주요 버튼들>)` → `page.screenshot()` → URL 체크. 클릭 후 라우트가 404가 아닌지 코드로 확인.

**3단계** — dead-link 정적 분석을 PR/커밋 전 자동 실행. `href` 없는 `<a>`·`<Button>`, 클릭 핸들러 없는 클릭 가능 `<div>`를 코드 단에서 잡아낸다.

**4단계** — **자기 검증 금지** 강제. Task Agent와 Verification Agent를 다른 인스턴스(#9 편제 / #27 Agent Teams)로 분리. 같은 컨텍스트에서 자기 코드를 자기가 통과시키면 SKILL_ATLAS 사고 재발한다.

**5단계** — 사용자 여정 KPI 명시. 예: "랜딩 페이지 주요 버튼 4개 이상 클릭 시 각각 올바른 라우트로 네비게이트", "Lighthouse 80→95", "E2E 12/12 통과".

## 본인 운용 패턴

UI 산출물은 *예외 없이* 다른 인스턴스가 Playwright로 클릭 검증한 뒤에야 Verified로 닫는다. 본인이 한 작업을 본인이 통과시키는 순간 SKILL_ATLAS가 다시 발생한다. 그래서 #9 편제 분대원 슬롯 1개를 *Verification 전담*으로 항상 비워둔다 — 비싸 보여도 무인 자동화의 가장 싼 보험이다.

dead-link 정적 분석은 pre-commit hook(#38)으로 박아두면 사람이 잊어도 시스템이 잊지 않는다. `href` 없는 `<a>`·`<Button>`, 클릭 핸들러 없는 클릭 가능 `<div>`만 잡아도 SKILL_ATLAS급 사고의 80%는 사전에 죽는다.
