# 31. 크롬 원격 데스크탑 활용해서 작업 시키기

## 한 줄 정의

물리 PC 5대 각각에 Claude Code 6개씩 띄워 **5 × 6 = 30개**를 동시에 굴리고, 외출 중에는 크롬 원격 데스크탑으로 휴대폰에서 그 30개에 접속하는 본인의 가로축 양적 확장 운용 표준.

## 왜 이 노하우가 중요한가

단일 PC 한 인스턴스로는 Rate Limit·컨텍스트·Compact가 곧바로 발목을 잡는다. 가로축으로 펼치면 *"한 인스턴스가 죽어도 29개가 살아있다"* 는 회복 탄력성이 생긴다. 더 결정적인 건 **모바일에서도 30개 전부에 접근**된다는 점. 외출 중·이동 중에도 휴대폰으로 크롬 원격 데스크탑(RDP)을 띄워 30개의 진행을 보고, 가장 막힌 한 인스턴스만 원격으로 한두 메시지 던져 풀어준다. 누적 운용 결과, **하루 24시간 중 AI가 일하지 않는 시간이 사실상 0**에 가까워진다. *"#10 트랙터 운전"* 의 가장 극단적 형태이며, 본 시리즈 전체의 운용 무대다.

## 핵심 개념

```
PC1 ─ inst1, inst2, inst3, inst4, inst5, inst6
PC2 ─ inst7, ..., inst12
PC3 ─ inst13, ..., inst18
PC4 ─ inst19, ..., inst24
PC5 ─ inst25, ..., inst30
              ↑
   크롬 원격 데스크탑 (모바일 접속)
```

| 축 | 분담 |
|----|------|
| PC1·PC2 | 사고·기획 (Opus 위주, Plan Mode) |
| PC3·PC4 | 실행 (Sonnet, `--dangerously-skip-permissions`) |
| PC5 | 검증·헤드리스 (Haiku, `claude -p` 자동화) |
| 모바일 | 모니터링·짧은 개입 |

핵심 인프라: **#40 HUD**(30개 상태 한 화면), **#13 dangerously-skip-permissions** + **#26 Hooks**(가드레일), **#12 헤드리스 모드**(자동 루프), **#41 Git Worktree**(병렬 브랜치). 모바일 결과 전달은 글로벌 헌법대로 **클라우드 동기화 폴더**(Google 드라이브/OneDrive 등)에 `.txt`로 저장 — 폰에서 동기화 앱으로 즉시 확인.

## 실전 사용법

**1단계** — 5대 PC를 Tailscale + SSH 네트워크로 묶는다(`add-pc` 스킬). RDP는 보조 채널.

**2단계** — 각 PC에 Claude Code 6개를 폴더 분리로 띄운다. 같은 저장소면 **#41 Git Worktree**, 다른 저장소면 그냥 별 폴더.

**3단계** — `~/.claude/settings.json`에 statusLine·hooks·MCP 동일 세팅 동기화(**#20 G드라이브 백업** 활용).

**4단계** — 30개 운용 표준: 사고 6 + 실행 12 + 검증 6 + 자동화 헤드리스 6. Dual Mode(**#5**)를 PC 단위로 펼친 형태.

**5단계** — 모바일 운용은 *"읽고 짧게 개입"* 만. 긴 사고는 PC 앞에서. 휴대폰으로 던지는 메시지는 *"막힌 곳 한 줄 진단"* 수준으로 유지.

**KPI**: 30개 평균 가동률 ≥ 70%, Rate Limit 충돌로 30개 전부 멈추는 사건 ≤ 월 1회, 모바일 개입으로 풀린 막힘 ≥ 일 3건.

**비용 통제** — **#23 API 비용 최적화**, **#37 피크타임 회피**, **#4 /model**로 모델 배분.

> Vault 사례: `claude-platoons-control/wiki/2026_05_03_21.07_import_CPC_ARCHITECTURE_OVERVIEW.md` 는 본인이 5개 프로젝트 × 3소대 + trader-bot 도합 16개 소대를 CPC(Supabase + Vercel)로 등록·라우팅한 실전 기록이다. 30개 인스턴스를 5컴퓨터로 늘리는 물리적 확장이 단발 PC에서는 동시에 풀리지 않는다 — *명령 라우팅·상태(IDLE/RUNNING/PAUSED/DONE) 일원화·오프라인 버퍼링* 같은 중앙 인프라 한 겹이 같이 깔려야 30개가 무너지지 않는다. 본 항목의 *"30개 = 5컴퓨터 인프라 + 인지 부하 분산 + 인계 자동화"* 등식의 첫 항이 그 노트에서 구현체로 굳었다.

## 관련 항목

- **#14 군대 소대 편제** — 30개의 조직론
- **#41 Git Worktree** — 단일 PC 안의 세로 확장
- **#12 헤드리스 모드** — PC5의 자동화 채널
- **#40 Statusline HUD** — 30개 가시성 인프라
- **#13 --dangerously-skip-permissions** — 30개 무중단의 전제
