# 22. SVG 시각화 → 스킬 자산화

## 한 줄 정의

세 번째 같은 다이어그램을 그리기 시작했다면 그 자리에서 손을 멈추고 **반복 패턴 발견 → SVG 관계도/흐름도로 정리 → 스킬(`~/.claude/skills/`) 로 박아 넣어 다음번에 한 줄 호출로 재현**되도록 만드는 — AI 운용을 점진적으로 자동화하는 자산화 3단계 루프.

## 왜 이 노하우가 중요한가

본인 4,000시간 누적에서 가장 비싸게 산 교훈은 *"같은 그림을 두 번 이상 그리고 있으면 그건 작업이 아니라 누락된 자산"* 이라는 사실이다. AI 운용 초기에는 다이어그램·플로우차트·아키텍처 도식을 매번 새로 그렸다. ChatGPT에게 설명하고, Claude에게 다시 설명하고, 사흘 뒤 같은 도식을 또 그렸다. 30개 동시 운용으로 들어가면서 이 비용이 본격적으로 보이기 시작했다 — *같은 구조도를 30번 새로 설명하느라 하루가 사라진다*.

해결책은 단순하다. **반복이 보이는 순간 시각화하고, 시각화한 순간 스킬로 박는다.** 이 3단계 — 패턴 발견 → SVG 자산 → 스킬 호출 — 는 분리될 수 없다. 1단계만 하면 머릿속에 있는 채로 다시 잊히고, 2단계에서 그치면 SVG 파일이 G드라이브 어딘가에 묻혀서 두 번 다시 안 열린다. 3단계까지 가야 *"/architecture-svg V60 구조도"* 한 줄로 같은 품질이 재현된다.

이게 본인이 슬라이드 39번(HTML+Vercel 신속 배포)·#18(Slash Commands)·#20(MCP 서버) 와 묶어 *"개인 자산 인프라"* 라고 부르는 이유다. SVG 자산화는 가장 가시적인 자산 — 결과물을 눈으로 확인할 수 있고, 스킬화 후 즉시 효용이 측정된다. *"같은 도식 그리는데 어제는 25분, 오늘은 90초"* 가 KPI다.

또 하나 — SVG는 **확대해도 깨지지 않고, 텍스트가 그대로 검색되며, Git diff 가 가능하다**. PNG로 만들어 G드라이브에 던져두는 것과 차원이 다른 자산이다. 본인 특허 10-2026-0009425 SAL Grid 의 3차원 좌표 구조도 SVG로 정리해 두었기에 출원서·발표자료·강의자료에서 매번 동일한 그림이 나간다.

## 핵심 개념

### 자산화 3단계

| 단계 | 트리거 | 산출물 | 시간 |
|------|--------|--------|------|
| **1. 반복 패턴 발견** | 같은 구조 설명 3회째 | 종이/메모 스케치 | 즉시 |
| **2. SVG 관계도/흐름도** | 1단계 통과 즉시 | `.svg` 파일 (1900px 표준) | 30~90분 |
| **3. 스킬 자산화** | SVG 1회라도 재사용 시도 시점 | `~/.claude/skills/{이름}/SKILL.md` | 30분 |

3단계까지 가지 않으면 자산이 아니다 — 그냥 파일 하나일 뿐. 본인이 보유한 스킬 셋 중 시각화 계열 (`architecture-svg`, `create-image-기본`, `image-기본`, `ai-image-기본`) 은 모두 이 3단계를 거쳐서 박혔다.

### 어떤 그림을 SVG로 만드는가

`create-image-기본/SKILL.md` 의 Decision Tree가 명확한 기준을 준다 — *"조직도/플로우차트/구조도인가? → YES → SVG"*. 즉 박스와 화살표·계층 관계·테이블형 매트릭스가 보이면 SVG. 사진·일러스트·UI 프로토타입은 SVG 대상이 아니다 (`ai-image-기본` 으로).

```
이미지가 필요하다
  ├─ 표준 다이어그램(시퀀스/간트/ER) → Mermaid
  ├─ 복잡한 표·대시보드          → HTML→PNG
  ├─ 조직도/플로우차트/구조도    → SVG  ← 여기
  ├─ 사진/합성                    → Pillow / ai-image
  └─ 모름                          → HTML
```

### `architecture-svg` 스킬의 V50 골격 (자산화 표본)

본인 V50 아키텍처 SVG 가 *스킬화 표본* 이다. 색상 팔레트·컬럼 레이아웃·행 높이 계산·HTML 엔티티 화살표 처리 — 이 모든 결정이 SKILL.md 에 박혀 있어 다음 V60·V70 작성이 한 줄 호출로 끝난다.

| 표준 | 값 |
|------|------|
| 캔버스 폭 | 1900px (한국어 가독 + 발표 슬라이드 매핑) |
| 폰트 | `'Malgun Gothic', 'Apple SD Gothic Neo', sans-serif` |
| 헤더 | h=68, 진남색 `#0f172a` + 회색 부제목 |
| 섹션 색상 순환 | 파란/초록/남/보라/갈/청 (1~6) |
| 화살표 | `&#x2192;`(→) `&#x2014;`(—) — 깨짐 방지 HTML 엔티티 강제 |
| 첫 컬럼 데이터 x | ≥ 22 (border x=5 기준, 그 이하면 잘림) |

이 6줄을 매번 새로 결정하지 않게 만든 것이 자산화의 본질이다.

### SAL Grid Viewer 3D 시각화 사례

본인이 SAL Grid 개발방법론(특허 10-2026-0009425)을 시각화할 때 *Stage × Area × Level* 3차원 좌표를 처음에는 표로 그렸다. 표는 1차원 정보라 3차원이 안 보였다. 두 번째 시도에서 SVG 입체 격자, 세 번째 시도에서 Three.js 기반 3D Viewer (`viewer_database.html`) 로 진화했다 — 정확히 *반복 패턴 → 시각화 → 스킬 자산* 의 진화 경로다. 이 Viewer 는 청룡 스킬(`청룡-sal-grid-dev`) 에 박혀 SAL Grid 프로젝트가 자동 감지되면 같은 시각화가 즉시 재현된다.

### `create-image-기본` 의 위임 패턴

스킬화 시 또 하나 박아야 할 것은 **누가 그릴 것인가**. `create-image-기본` 은 sonnet 서브에이전트에게 위임하는 프롬프트 템플릿을 통째로 가지고 있다 (단순 변환=haiku, 복잡 디자인=sonnet). 본인 메인 세션은 지휘만 하고 실제 SVG 작성은 분대원이 한다 — 메인 컨텍스트 보호 + 병렬 처리. 이 위임 구조까지 SKILL.md 에 박혀야 진짜 자산이다.

## 실전 사용법

### 자산화 트리거 판단

| 신호 | 판단 |
|------|------|
| 같은 구조 설명 3회째 | 즉시 시각화 착수 |
| 발표·문서·코드 주석에 같은 도식 분산 | SVG 단일 출처(SSOT) 화 |
| AI에게 "그림으로 정리해 줘" 입력 횟수 ≥ 5 | 스킬화 임계점 도달 |
| 신규 프로젝트 첫 30분이 구조 설명에 소진 | 자산 부재 = 자산화 필수 |

### 6단계 운용

**1단계 — 반복 발견 즉시 SVG 1차 스케치**. 종이·iPad·Excalidraw 등 어디든. *"이 그림을 또 그릴 가능성이 있는가"* 만 자문한다. YES면 1900px SVG로 진입.

**2단계 — `architecture-svg` 스킬 호출**. *"/architecture-svg {제목} 섹션: ① ② ③ 저장: {경로}.svg"* 한 줄. V50 표본을 자동 Read 하고 동일 스타일로 작성된다. 본인이 SVG 좌표 계산을 직접 할 일은 없다.

**3단계 — 검증 체크리스트 통과**. SKILL.md 마지막 9개 항목을 자동 검증 — 화살표 HTML 엔티티 / 첫 컬럼 x≥22 / 컬헤더 가운데정렬 / 한글 폰트 선언 / 섹션 border / 색상 일관성. 9개 중 하나라도 실패면 재작성. *"보이는데 그럭저럭 됐어"* 식의 자체 평가는 금지 (자기 검증 금지 원칙).

**4단계 — Vercel 신속 배포 (#18과 결합)**. SVG 단독 배포보다는 HTML 래퍼 + `noindex` 메타태그로 URL 아는 사람만 볼 수 있게 — 검색엔진 노출 차단. `vercel-private-url-배포` 스킬과 짝.

**5단계 — 스킬화 의사 결정**. 같은 SVG를 2회 이상 재사용했거나 재사용할 가능성이 명확하면 즉시 `~/.claude/skills/{이름}/SKILL.md` 작성. 한 번 쓴 SVG 도 *향후 1년 이내 재사용 가능성 ≥ 30%* 면 스킬화. 본인 기준은 보수적으로 잡는다 — 보유 스킬을 늘리는 것보다 *키워둔 스킬 중 실제 매주 호출되는 코어*를 좁히는 쪽이 훨씬 가치 있다.

**6단계 — KPI 측정**. *"같은 도식 두 번째 작성 시간 / 첫 번째 작성 시간"* 비율. 본인 운용 기준 스킬화 성공 시 0.05~0.15 (즉 첫 30분 작업이 두 번째에 90초~4분). 비율이 0.5 이상이면 스킬화 실패 — SKILL.md 가 충분히 구체적이지 않다는 뜻.

### 본인 운용 패턴

SVG 자산화는 발표자료·특허·강의자료 3개 라인을 동시에 살린다. 본인은 강의자료(`MagicShow강의자료`) 50장 슬라이드를 만들 때 같은 SAL Grid 도식을 14번 슬라이드(SAL 3차원 좌표) · 35번 슬라이드(SAL Grid) · 부록에서 재사용했다 — 한 번 그린 SVG 가 3장의 슬라이드를 책임진다.

자산화 후 1개월 운용 KPI — 도식 1개당 평균 재사용 4.7회, 신규 작성 시간 절감 누적 약 18시간. 작아 보이지만 *4종 품질관리(#28) · MBO 합의(#8) 같은 다른 자산화와 합쳐 누적되면* 30% 시간 절약이 된다. *(측정: 본인 1개월간 SVG 호출 로그 + 다른 자산화 스킬 누적 호출 카운트 기준 자기 측정치)*

> Vault 사례: `333-knowledge-share/wiki/SVG_DRAWING_GUIDE.md` 가 본인 특허 도면 SVG의 표준 자산이다. *"방식: 블록 다이어그램(직사각형 박스 중심) / 색상: 흑백만(특허청 규정) / 주요 구성부명·참조번호: 28px bold / 설명 텍스트: 24px / 참조번호: (번호) 형태"* 같은 표준 한 페이지가 적혀 있다. 이 한 페이지를 보면 본인 특허 4건(SAL Grid·MyChatbot·Platoon·BuzzLab)의 도면 24장(=8장 × 3특허) 과 BuzzLab 14장이 모두 같은 양식을 공유하는 이유가 보인다. 본 항목 §6단계 KPI(*두 번째 작성 시간 / 첫 번째 작성 시간 ≤ 0.15*) 가 가장 잘 작동한 사례 — 이 가이드 한 장 덕에 도면 첫 장 30분 → 두 번째 장 3분이 된다.
