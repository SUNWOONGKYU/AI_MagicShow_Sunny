# 26. 유튜브 영상 한방에 제작하기 → 유튜브에 1일 1영상 올리기

## 한 줄 정의

기획(Plan-A 벤치마크형 / Plan-B 원본형) 2트랙과 제작(Produce) 1엔진을 한 스킬(`/youtube-기본`) 아래로 통합하고, 헤드리스 모드(#10)와 멀티 모델 이미지 제작(#23)을 결합하여 사람의 손이 단 한 번도 GUI에 닿지 않는 채로 1일 1영상을 양산하는 본인의 영상 자동화 인프라.

## 왜 이 노하우가 중요한가

유튜브 1일 1영상은 사람을 갈아 넣어 푸는 문제가 아니다. 본인이 실제로 시도한 모든 *수동 GUI 도구* — Vrew·Whisk·나노바나나(수동 모드) — 는 50씬짜리 10분 영상에서 일관되게 같은 한계에 부딪혔다. 한 씬 수정에 5분, 50씬이면 250분, 한 편 만드는 데만 4시간이 사라진다. 거기에 컷 편집·BGM·자막 동기화까지 손으로 잡으면 1일 1영상은 물리적으로 불가능하다. 4,000시간 누적 운용에서 본인이 가장 먼저 폐기한 것이 *손으로 자르는 모든 단계*다.

문제의 본질은 "AI가 영상을 만든다"가 아니라 **"파이프라인이 사람 없이 끝까지 흐르는가"** 다. 이미지 한 장만 사람이 채택해도, 자막 한 줄만 손으로 고쳐도, 컷 한 곳만 GUI로 잡아도 — 그 한 점에서 자동화는 끊어진다. 끊어진 자동화는 자동화가 아니라 *반자동 노동*이다. 본인이 만든 `youtube-기본` 스킬의 SSOT 한 줄 — *"사용자는 진입점 1개만 기억하면 된다: `/youtube-기본`"* — 은 이 절단점을 모두 봉합한 결과다.

기존 도구·서비스 — Vrew, Whisk, Sora 자동 생성 — 가 못 하는 세 가지가 있다. 첫째, **씬 단위 부분 재합성**. 50씬 중 23번 씬 한 곳만 음성을 다시 뽑고 그 자리에만 갈아끼우는 작업이 GUI 도구에선 사실상 불가능하다. 둘째, **anchor regex 자동 정렬** — Whisper STT 결과를 대본 키워드와 정규식으로 매칭해 SRT를 0.1초 단위로 자동 동기화하는 처리. 셋째, **MBO 6기준 채점 루프**. 타이포·색감·정보밀도·균형·임팩트·나레이션 정합성 6기준에 씬당 120점 만점 채점이 자동으로 돌아가야 "이 편을 올려도 되는가"가 결정된다. 이 셋이 빠지면 1일 1영상은 한 달을 못 간다.

본인이 실측한 두 사례가 이 골격의 실효성을 증명한다. **BuzzLab AI 챔피언 출품작(2026-04-22)** — 28씬 / 177.67초 / 70 MB / v5 채점 **2,251점/2,400점(93.8%)**. **Sunny's QC 4종 소개(2026-04-29)** — 50씬 / 641.23초 / 34.16 MB / **anchor 49/50 매칭(98%)**. 둘 다 사람이 GUI에 손댄 시간 0초. 1일 1영상이 가능한 것은 이 0초 때문이다.

## 핵심 개념

### 2-Phase 파이프라인 — Plan(2트랙) → Produce(1엔진)

`/youtube-기본` SKILL.md(SSOT) 그대로 옮기면:

```
Phase 1: PLAN (기획) — 트랙 분기
  ├─ Plan-A (벤치마크형) — 경쟁 영상 분석 → 같은 톤으로 재구성
  └─ Plan-B (원본형)    — 내 자료 → 분량 추정(1초≈5.7자) → 대본 4회 개정
        ↓ (양 트랙 동일 산출 형식으로 수렴)
Phase 2: PRODUCE (제작) — 1 엔진 공통
  S2  ElevenLabs TTS → Whisper STT → SRT 교정
  S3  Multi-Source Best-of-N 이미지 + 다이어그램 페어
  S4  FFmpeg zoompan/concat/xfade + tail-pad 6~8s
  S5  MBO 6기준 120점/씬 검증 + Hook BPI + BGM
  S6  YouTube 배포 (영문 SRT 4단계)
```

진입점 1개, 트랙 2개, 엔진 1개. **트랙은 입력만 다르고 출력 형식과 이후 파이프라인은 동일**하다는 점이 핵심이다. 벤치마크 영상 URL을 던지든, 본인 자료 PDF를 던지든, S2부터의 처리 골격은 한 줄도 바뀌지 않는다.

### 정적 인코딩 SSOT (`video-frames-기본`)

영상 프레임 표준은 별도 SSOT 스킬이 잡는다.

| 항목 | 값 |
|------|-----|
| 해상도 | 1920×1080 PIL 정적 |
| 음성 | ElevenLabs TTS per-scene |
| 인코딩 | FFmpeg CBR 2500k |
| `tail_pad` | 8.0초 권장 (마지막 발화 잘림 방지) |
| `total_duration` | 모든 씬 duration 합 + tail_pad |
| 표준 디렉토리 | `episode_NN/output/scenes/scene_NN.png` + `audio_scenes_v?/scene_NN.mp3` + `segments_titled.json` |

50씬을 한 번에 자르는 도구 대신, **씬 단위 PNG + 씬 단위 MP3 + JSON 타이밍**을 분해 보관한다. 그래서 23번 씬만 갈아끼우는 부분 재합성이 1분 만에 끝난다. POLFAI EP01-03(3편 시리즈)에서 검증된 패턴 그대로 가져온다.

### Multi-Source Best-of-N 이미지 (#33과의 결합)

이미지가 자동화의 가장 큰 함정이다. 단일 모델 일괄 생성은 50씬 후 재작업 비용이 폭발한다. SSOT 절차:

1. 샘플 5씬을 **5모델 × 3장 = 15장** 후보로 생성 (Gemini Image Preview, GPT Image / DALL-E, FLUX, Ideogram, Recraft)
2. MLLM 채점 → 모델별 베스트 선정
3. 채택 모델로 나머지 45씬 일괄 생성
4. Pillow 후처리(텍스트 오버레이·트림·블러)

이 5씬 게이트를 거치지 않고 50씬 일괄로 가면 23번에서 톤이 깨져 22씬을 다시 그려야 한다. Best-of-N의 본질은 *작은 표본 검증으로 큰 일괄 비용을 보호*하는 것이다.

### MBO 6기준 채점 — 씬당 120점

`shared/mbo-rubric.md`의 6기준을 자동 채점:

| 기준 | 만점 | 평가 포인트 |
|------|------|------------|
| 타이포 | 20 | 폰트 일관성·한글 자간·줄높이 |
| 색감 | 20 | 팔레트 13컬러 준수·콘트라스트 |
| 정보밀도 | 20 | 1씬 1메시지·과적재 회피 |
| 균형 | 20 | 좌우·상하 무게중심 |
| 임팩트 | 20 | 핵심 한 단어 시각화 |
| 나레이션 정합성 | 20 | TTS 발화와 화면 anchor 일치 |

50씬이면 6,000점 만점. v5 채점 2,251/2,400(28씬 출품작)은 **씬당 평균 80.4점, 만점 대비 67%이지만 v5 룰의 가중 환산 결과 93.8% 합격선 통과**. 출품작·튜토리얼류는 v5 가중 90% 이상, 일상 업로드는 단순 평균 80% 이상이면 업로드 가능 라인. 이 룰이 자기 검증 금지(Task Agent ≠ Verification Agent) 원칙에 따라 **별도 채점 에이전트가 수행**한다 — 만든 에이전트가 자신을 채점하면 *curl 200 ≠ 동작함* 사고가 그대로 재현된다.

### Glossary 사전 컨펌 — 약어 오류 차단

S1 단계에서 PO에게 강제로 묻는 단계. *"BPI"가 BuzzLab Prediction Index인지 Business Process Improvement인지를 TTS 전에 확정* 하지 않으면 발화는 한 번 잘못 나가고 50씬을 다시 뽑아야 한다. `shared/glossary-template.md`가 이 컨펌을 강제한다. 본인 운용에서 가장 비싼 사고가 약어 오발음이었다 — 한 번 겪고 표준에 박았다.

## 실전 사용법

### 1단계 — `/youtube-기본` 진입 (트랙 결정)

```bash
# Plan-A 벤치마크형
/youtube-기본 "건강정보_소재.txt 로 인기 유튜브 영상 분석하고 같은 톤으로 만들어"

# Plan-A 강제
/youtube-기본 "이 URL 분석해서 따라 만들어 https://youtu.be/xxx" --track plan-a

# Plan-B 원본형 — 발표·소개·내 자료 기반
/youtube-기본 "BuzzLab 팀 3분 소개 영상" --track plan-b

# Plan-B 50씬 10분급
/youtube-기본 "Sunny's QC 4종 소개, 50씬 10분, anchor regex 정렬" --track plan-b
```

키워드 매핑이 자동 라우팅한다. *벤치마크/경쟁영상/리서치/유튜브검색* 류 → Plan-A, *발표/소개/팀소개/제품시연/내자료로* 류 → Plan-B. 모호하면 1줄 질문으로 결정.

### 2단계 — Plan 트랙 실행 (대본·glossary·씬 시나리오)

Plan-B 원본형 기준 4개 산출물이 떨어진다.

| 산출물 | 위치 | 검증 게이트 |
|--------|------|-------------|
| 발표문_스크립트.txt | `output/script/` | 분량 추정 1초≈5.7자 ±10% |
| glossary.md | `output/glossary/` | PO 사전 컨펌 (필수) |
| 씬 시나리오 + anchor regex | `output/scenes/scenario.md` | anchor 매칭 시뮬 |
| 메타데이터 | `output/meta/` | 제목·태그·썸네일 카피 |

대본 4회 개정 루프(초안 → 톤 보정 → 분량 보정 → 약어 검사)를 거친 뒤에야 S2로 넘어간다. 4회를 줄이면 50씬에서 3씬 이상이 깨진다 — 본인이 측정한 임계값이다.

### 3단계 — Produce S2~S6 자동 흐름

```
S2 ElevenLabs per-scene TTS → Whisper STT → SRT 교정
S3 Multi-Source Best-of-N 이미지 (5씬 샘플 게이트 → 일괄)
S4 FFmpeg zoompan/concat/xfade + tail_pad 8s
S5 MBO 6기준 120점/씬 채점 + Hook 카피 BPI + BGM 페어링
S6 YouTube 영문 SRT 4단계 업로드
```

여기까지 사람이 클릭하는 GUI는 **0개**. 한국어 SRT는 YouTube가 무한 실패하므로 **영문 파일명 + BOM 제거 + LF**가 강제된다 — 이거 하나 빠지면 업로드 자체가 실패한다.

### 4단계 — #12 헤드리스 모드 결합 (진짜 자동화 완성)

여기가 *1일 1영상*이 *실제로 1일 1영상이 되는* 지점이다. 종합정리 #10 그대로:

> "`claude -p` 헤드리스 모드로 자동화하기 — 대화형 UI 없이 명령줄에서 한 번에 호출. 셸 스크립트·크론·CI 파이프라인에 통합 가능. 매일 새벽 자동 실행, 폴더 100개 파일 일괄 처리 등. 26번 1일 1영상의 진짜 자동화 인프라."

크론 한 줄로 묶는다.

```bash
# 매일 새벽 4시 — 어제 만든 소재 폴더로 영상 1편
0 4 * * * cd ~/projects/daily-video && claude -p "/youtube-기본 daily_seed/$(date +%Y%m%d).md --track plan-b" --dangerously-skip-permissions
```

`--dangerously-skip-permissions`(#35)는 Hooks(#11)의 PreToolUse 가드와 *반드시* 짝으로 운용한다. 한쪽만 쓰면 사고, 양쪽을 짝으로 쓰면 1일 1영상이 *진짜로* 돌아간다.

### 5단계 — #33 멀티 모델 이미지 제작 결합

이미지 자동화 절차 SSOT(`ai-image-기본/SKILL.md`)와 직결. 5모델 × 3장 = 15장 후보 → MLLM 채점 → 베스트 채택 → 일괄. 단일 모델 일괄 생성은 본인 운용에서 *결국 두 번 일하게 만든다*. Best-of-N는 비싸 보이지만 재작업을 막아 총비용이 더 낮다 — #47(API 비용 최적화)와 결합해 모델별 단가표로 매번 재계산.

### 6단계 — 검증 사례 그대로 따라가기

`/youtube-기본 SKILL.md` 검증 사례 표:

| 사례 | 트랙 | 분량 | 결과 |
|------|------|------|------|
| BuzzLab AI 챔피언 출품작(2026-04-22) | Plan-B | 177.67초 / 28씬 / 70 MB | v5 채점 2,251/2,400 (93.8%) |
| Sunny's QC 4종 소개(2026-04-29) | Plan-B | 641.23초 / 50씬 / 34.16 MB | anchor 49/50 매칭 (98%) |

처음 1일 1영상을 시도하는 사람은 이 두 사례의 segments.json·glossary.md·MBO 채점 결과를 복제해 자기 자료에 갈아끼우는 것으로 시작하면 된다. **검증된 골격을 베끼는 것이 시행착오를 단축하는 가장 빠른 길** 이다.

### 7단계 — `weekly-opinion-report` → 영상 파이프 결합

본인 별도 운용. 정치인 주간 여론 보고서(15페이지 HTML, 정당 컬러 자동 반영)를 만든 뒤, 그 보고서를 그대로 **Plan-B 원본형 입력**으로 넘긴다.

```bash
/weekly-opinion-report  # → 후보명_온라인여론분석_주간보고서_기간.html 산출
/youtube-기본 "후보명_..._보고서.html, 50씬 10분, anchor regex 정렬" --track plan-b
```

보고서 한 편 → 영상 한 편. 매주 자동 생성. 콘텐츠 공급원이 끊기지 않으면 1일 1영상은 노력이 아니라 *시스템*이 된다.

## 본인 운용 패턴

폐기한 것을 분명히 하는 것이 중요하다. **Vrew·Whisk·나노바나나(수동 GUI)는 2026-05-06부로 미사용**. 단일 이미지 도구 일괄 생성·한글 SRT 파일명 업로드·수동 자막 합치기는 *모두 자동화의 적*이다 — `youtube-기본 SKILL.md`의 폐기 항목 표가 이걸 명문화하고 있다.

또 하나의 본인 룰: **자기 영상은 자기가 채점하지 않는다**. SAL Grid의 *Task Agent ≠ Verification Agent* 가 영상 도메인에서 그대로 작동한다. 만든 에이전트가 MBO 6기준을 채점하면 80% 이하 영상도 90%로 통과시킨다 — 사람과 동일한 편향이다. 별도 채점 에이전트로 강제 분리. 30개 인스턴스 운용에서 이 원칙은 *영상 도메인의 curl 200 ≠ 동작함* 사고를 막는 마지막 선이다.
