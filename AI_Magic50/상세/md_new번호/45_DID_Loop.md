# 45. Data → Information → Decision의 Loop 이해하고 활용하기

## 한 줄 정의

원시 데이터(Data)를 의미 있는 정보(Information)로 가공하고, 그 정보를 의사결정(Decision)으로 연결한 뒤, 의사결정의 결과를 다시 데이터로 회수해 **다음 사이클의 입력**으로 돌리는 3단 순환 사고 루프(이하 DID Loop). 본인이 누적 운용 끝에 정립한 본인 고유 사고 모델이며, **SAL Grid(특허 출원 10-2026-0009425)와 별도로 DID 특허 명세서 v2.0 작성 완료·KIPO 출원 검토 단계**다(등록 가능성 평가 75-85%). SAL Grid가 작업의 골격이라면, DID Loop는 작업자의 머릿속 골격이다.

## 왜 이 노하우가 중요한가

Claude Code 30개 동시 운용에서 가장 흔한 사고는 *"데이터는 잔뜩 쌓였는데 의사결정이 흔들리는"* 상태다. 본인이 누적 운용 끝에 발견한 것은 — 사람들은 데이터와 정보와 의사결정을 **같은 단어로 섞어 쓴다**는 것. 그래서 *"데이터는 충분한데 결정을 못 한다"* 거나 *"결정은 했는데 근거 데이터가 없다"* 같은 모순된 상태가 1인 운용·다인 운용 가리지 않고 발생한다. 이 모순의 원천은 데이터 → 정보 → 의사결정의 **층위 구분 부재**다.

본인이 글로벌 CLAUDE.md에 헌법으로 박은 *curl 200 ≠ 동작함* 사고가 그 산 증거다. *"curl 200으로 HTTP 상태 코드를 받았으니 동작한다"* 라는 판정 — 이것은 데이터 레이어 KPI다. 그러나 사용자가 실제 브라우저에서 *"시작하기"* 버튼을 눌렀을 때 href가 없어 무반응이었던 것 — 이것은 사용자 여정 KPI다. 두 KPI는 **층위가 다르다**. curl 200은 *Data*고, *"버튼이 클릭 시 올바른 라우트로 네비게이트한다"* 는 *Information*이다. 이 둘을 같은 층위로 보고 *"테이블에 데이터 있으니 끝"* 으로 넘긴 것이 사고의 원천이었다. DID Loop는 정확히 이 사고를 차단하기 위한 본인의 사고 인프라다.

또 하나 — DID Loop 없이는 **Stage Gate를 통과시킬 수 없다**. 청룡 SAL Grid 스킬 §8.2의 5단계 리포트(누락 점검 → 정합성 체크 → AI 자동 검증 → Stage Gate 리포트 → PO 승인)는 본질적으로 *"데이터로 정보 만들고, 정보로 의사결정 끌어내고, 의사결정 결과를 다시 데이터로 회수하는"* DID Loop의 운용 형태다. 사람이 이 루프를 머리로 못 돌리면, 시스템 위의 5단계 리포트가 형식만 남고 알맹이가 빈다.

이 사고 모델이 시스템으로 외화된 형태가 본인 KIPO 출원 검토 단계의 **DID 특허 명세서 v2.0**이다 — 3 레이어 순환 구조와 4대 차별점(3차원 좌표 분류 + 4 서브 엔진 동시 병렬 + 조직 계층별 알고리즘 + 순환 루프), 청구항 23개, 등록 가능성 75-85% 평가까지 정리되어 있다. 기술 상세는 별도 자료로 분리: **[#45 DID 특허 설명자료](patent/45_DID_특허.html)**. 본 챕터는 그 시스템을 만들기 전에 작업자의 머릿속에서 먼저 작동해야 하는 **사고 모델**에 집중한다. SAL Grid가 산출물의 골격을 잡아주지만, 그 산출물을 만드는 사람의 머릿속 사고 모델이 흔들리면 골격이 비어버리기 때문 — 사고 모델 자체를 별도로 권리화하는 이유다.

## 핵심 개념

### 3 레이어 구분 (가장 중요)

| 레이어 | 정의 | 예시 (UI 작업) | 예시 (정치 분석) |
|--------|------|----------------|-----------------|
| Data | 가공 전 측정값 | curl 200 응답코드 · 페이지 로드 시간 1.2s | 댓글 12,341건 수집 · 좋아요 합계 |
| Information | 의사결정에 쓰일 의미가 부여된 가공물 | "주요 버튼 4개 중 3개가 href 누락" | "지역별 부정 감성 비율 상위 3위" |
| Decision | 행동 강제력 있는 판단 | "Verification 실패 → Needs Fix" | "유세 동선 우선순위 재배치" |

이 표는 단순해 보이지만 실제 운용에서 80% 이상이 무너지는 곳이 *"Data를 Information인 양 다루는 지점"* 이다. 본인이 글로벌 CLAUDE.md에 박은 *"curl 200 ≠ 동작함"* 은 정확히 이 경계 위반을 막기 위한 헌법이다.

### 루프 4단계 (D → I → K → 회수)

```
[수집] Data
   ↓ 가공·집계·필터·정규화
[해석] Information
   ↓ 기준선·KPI·승인 체계 통과
[판정] Decision
   ↓ 실행 + 결과 측정
[회수] Data (다음 루프 입력)
```

핵심은 **마지막 회수 단계**. 의사결정만 하고 결과를 데이터로 다시 거두지 않으면 루프가 아니라 단발 직선이다. 단발 직선 사고는 학습이 누적되지 않는다. 본인이 30개 인스턴스를 끊김 없이 돌릴 수 있는 이유는, 매 인스턴스가 자기 결정의 결과를 다음 사이클에 데이터로 다시 넣기 때문이다. SAL Grid의 grid_records JSON에 *"실행 결과 + 검증 결과"* 를 남기는 것이 사실상 회수 단계의 시스템 구현물이다.

### 데이터 레이어 KPI vs 사용자 여정 KPI

본인 글로벌 CLAUDE.md "UI 검증 철칙" 5항에 박힌 핵심 이중 KPI 구조.

| 종류 | 뜻 | 예 |
|------|------|------|
| 데이터 레이어 KPI | 시스템 내부 측정값 | "테이블에 데이터가 있다", "curl 200" |
| 사용자 여정 KPI | 사용자가 실제 화면에서 끝까지 도달하는가 | "랜딩 페이지 주요 버튼 4개 이상 클릭 시 각각 올바른 라우트로 네비게이트" |

데이터 레이어 KPI만 보고 *"끝났다"* 라고 결정하면 *"curl 200 ≠ 동작함"* 사고가 재현된다. DID Loop 관점에서 — *"데이터 레이어 KPI는 Data 단계이고, 사용자 여정 KPI까지 가야 Information이 된다"*. **두 KPI를 동시에 갖고 있어야 의사결정이 정당해진다.**

### #30(AI 오류 인정 + 창발) · #28(4종 품질관리)와의 짝

DID Loop는 단독으로 작동하지 않는다.

- **#30 AI 오류 인정 + 창발** — AI가 만든 결과물이 *"믿을 수 있는 데이터인지"* 를 의심하는 헌법. 데이터 입구에서 거짓을 거른다. 거르지 않으면 가짜 데이터로 만든 정보로 거짓 의사결정에 이른다.
- **#28 4종 품질관리** (`review-evaluate-코어1` · `pro-persona-debate-코어6` · `5times-debug-loop-코어3` · `주작-sal-da`) — 데이터 → 정보 단계의 가공 품질을 4가지 다른 칼날로 검증. 5기준 평가는 정보 합격선, Devil's Advocate 토론은 의사결정 직전 회의, 5회 디버그 루프는 회수 단계의 재시도, SAL-DA는 역방향 진단으로 회수된 데이터의 무결성 점검.

#30이 입구를 잠그고, #28이 가공 단계를 검증하고, DID Loop가 흐름의 골격을 박는 — 3개가 한 패다.

### Verification Agent와 회수 단계

DID Loop의 회수 단계가 작동하려면 **Task Agent ≠ Verification Agent** 가 강제되어야 한다. 자기가 한 의사결정의 결과를 자기가 데이터로 측정하면 측정 편향이 생긴다. 본인이 청룡 SAL Grid 스킬 §7.1과 글로벌 CLAUDE.md "자기 검증 금지" 헌법에 박은 이유. **회수 단계에서 측정자는 항상 의사결정자와 분리되어야 한다** — 이것이 DID Loop의 무결성 핵심이다.

### 루프 1회의 시간 단위 (운용 KPI)

본인 운용에서 30개 인스턴스 각각의 DID Loop 1회 표준 시간은 다음과 같이 잡혀 있다.

| 작업 유형 | 1 Loop 표준 시간 | 회수 산물 |
|-----------|------------------|----------|
| Task 1건 (코드 작성) | 5~30분 | grid_records JSON 1건 업데이트 |
| Stage 전체 (Stage Gate) | 2~6시간 | Stage Gate 리포트 1건 + MBO 결과보고 |
| 프로젝트 1개 | 수일~수주 | TASK_PLAN 진행률 % + Cluster Audit 리포트 |
| 사고 모델 자체 (메타) | 분기 1회 | DID Loop 정의 갱신 (본 문서가 그 산물) |

3개 시간 스케일에서 동일한 루프 구조가 반복된다 — 5~30분 Task에서도 DID Loop, 분기 1회 메타 차원에서도 DID Loop. **시간 스케일 불변성**이 본 사고 모델의 가장 강력한 속성이며, 특허 검토 대상으로 꼽은 이유 가운데 하나다.

## 실전 사용법

### 1단계 — 작업 시작 시 *"내 데이터는 무엇인가"* 1줄 정의

작업 들어가자마자 입력 데이터 출처를 1줄로 박는다. 예: *"입력 데이터 = 댓글 pkl 12,341건 + 썸트렌드 xlsx 3개월치"*. 이 줄이 비면 그 작업은 데이터 없이 시작된 작업이고, 결과는 모래성이다. 본인은 이 1줄을 MBO 목표 정의서 첫 항목으로 박는다(`mbo-코어5` 스킬 양식).

### 2단계 — Data → Information 가공 시 KPI 명시

가공 단계에서 *"이 정보의 합격선이 무엇인가"* 를 KPI로 박는다. 데이터 레이어 KPI 1개 + 사용자 여정 KPI 1개, 두 개 짝으로. 한쪽만 박으면 *"curl 200 ≠ 동작함"* 사고가 재발한다.

### 3단계 — 의사결정 직전 #30 + #28 적용

- #30 — *"AI가 만들어낸 정보 중 거짓일 가능성 있는 항목"* 을 명시. AI 오류 인정 헌법 발동.
- #28 — `review-evaluate-코어1` 5기준 평가 + `pro-persona-debate-코어6` Devil's Advocate 토론. 정보가 의사결정으로 격상되기 전 마지막 검증.

이 2단 검증을 통과한 정보만 의사결정 입력으로 인정한다.

### 4단계 — 의사결정 명시화 (단어 선택 강제)

*"좋아 보임"*, *"괜찮은 듯"* 같은 모호한 단어를 의사결정 단계에서 금지. 본인 운용은 5종 동사로 잠근다 — **승인 / 반려 / 보류 / 재검토 / 지연**. 이 5종 외 표현은 의사결정으로 인정하지 않는다. SAL Grid의 Stage Gate에서 PO 승인 단계 5종 동사를 그대로 가져온 형태다.

### 5단계 — 회수 단계 강제

의사결정 직후 *"이 결정의 결과를 어떤 데이터로 측정할 것인가"* 를 정의. 정의 안 하면 회수 안 됨. 본인은 grid_records JSON의 *"검증실행 4속성"*(검증시각·결과·점수·증빙)을 회수 단계의 표준 슬롯으로 사용한다. 이 4속성이 채워지지 않으면 Task가 Verified로 전환되지 않는다 — 시스템이 회수를 강제한다.

### 6단계 — 다음 루프 입력으로 전달

회수된 데이터를 다음 사이클의 *"내 데이터는 무엇인가"* 1줄로 다시 박는다. 이러면 30번 루프 후 30번째 입력 데이터에 1번 루프부터 누적된 결과가 다 들어있다. SAL Grid Recorder가 이걸 자동으로 한다는 것이 사고 인프라가 시스템 인프라로 외화된 지점이다.

### 7단계 — 분기 1회 메타 차원 루프 점검

분기 1회, 본인 사고 모델 자체에 DID Loop를 한 번 적용한다. 지난 분기 의사결정 데이터(승인·반려·보류 횟수와 사후 결과)를 모아서 정보화하고, *"내 사고 모델 어디가 흔들렸는가"* 를 메타 의사결정한다. 이 문서(45번)도 그 메타 회수의 산물이다.

## 본인 운용 패턴

본인이 누적 운용에서 발견한 단 하나 — **데이터·정보·의사결정을 같은 단어로 섞어 쓰는 순간 작업은 무너진다**. 다인스턴스 운용에서 이 3단 구분 없이는 1주일을 못 버틴다. 본인은 슬라이드 강의에서도 이 3단 구분을 가장 먼저 칠판에 그린다 — *"여러분이 지금 손에 든 게 데이터인가요, 정보인가요, 의사결정인가요?"* 이 한 줄 질문이 누적 운용의 압축이다.

또 하나 — DID Loop는 **외부에 위임할 수 없는 사고 인프라**다. SAL Grid는 시스템에 박을 수 있고, MBO는 양식에 박을 수 있다. 그러나 *"이건 데이터고 저건 정보다"* 라는 층위 구분은 작업자의 머리에서 일어나는 일이고, 그래서 본인은 이걸 별도 특허 검토 대상으로 꼽는다. SAL Grid가 외화된 골격이라면 DID Loop는 내화된 골격이다. 두 개가 한 쌍으로 본인 운용의 안팎을 받친다.
